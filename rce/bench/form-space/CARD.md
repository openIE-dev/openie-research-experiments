# Form corpus v1: dataset card

Workstream W1 of the RCE-JEPA programme (research.openie.dev/about/rce-jepa/):
Forms paired with intent statements and checker verdicts. Generated by
`scripts/corpus.py` of openIE-dev/rce at commit `145d2a8a` (merged to main
in PR #7) with the reference checker built from the same commit; the run is
a pure function of the checkout and the seed `0x5eedc0de0001`, and every
row names the commit. Registered in `PREREG.json` (hash sidecar, committed
at `00c8972` before the run).

## Files

| File | Rows | Content |
|---|---|---|
| `results/forms.jsonl` | 180 | one accepted program per distinct shape: `path`, `origin`, `licence`, `source_sha256`, `shape_hash`, `intent`, `source`, `nameless`, `verdict`, `form` (tokens, bytes, bits, gz_bits), `code` per target (tokens, bytes, bits, gz_bits, rho, rho_bytes, rho_gz, `runtime_prefix_verbatim`), `trace_heads`, `split`, `cpu_s` |
| `results/negatives.jsonl` | 883 | 343 conformance tests that must be rejected, with their diagnostic code and clauses; 538 token mutants of the accepted programs that the checker rejects, with the diagnostic and the mutation kind; 2 mutants the checker accepts (distinct shape from the parent) |
| `results/summary.json` | | counts, vocabularies, the rho statistics, the 104 refused candidates with the checker's reason |

## Provenance and licence

Every program is hand-written material of the openIE-dev/rce repository
(spec examples, the 0.9 examples, the programs and apps corpora, the book
listings, the standard library and the conformance suite's accept and
reject tests), dual-licensed MIT or Apache-2.0 by Open Interface
Engineering, Inc. The rows here are published under this repository's data
licence (CC BY 4.0) with the source licence named in each row. Nothing was
scraped from outside the project, and no model wrote any program in v1.

## Population and size

343 candidates by the registered rule; 239 accepted standalone by `rce
check`; 104 refused by rule (the `ill_typed/` examples are written to be
refused, modules of multi-file packages and standard-library modules that
need a package or the `#!lib` directive do not admit alone; each refusal
and its reason is in `summary.json`). 59 accepted rows share a shape with
another (the conformance suite repeats spec examples), so 180 distinct
shapes remain.

| origin | distinct shapes |
|---|---|
| spec-examples | 61 |
| conformance-accept | 35 |
| stdlib | 26 |
| book-listings | 19 |
| programs | 18 |
| spec-examples-0.9 | 18 |
| apps | 3 |

Form size, in tokens of the nameless canonical source: median 121
(interquartile range 68 to 240; smallest 6, largest 149,218, the IDNA
tables of the standard library). 21 programs have at most 50 tokens, 108
between 51 and 200, 22 between 201 and 1,000, 29 above 1,000. 43 programs
carry an `intent` block (the paired tier of the data plan); 46 have a state
region and 42 have a trace. 7 programs have no emitted form on any target
(the 0.9 capability and typed-output examples, which the emitters do not
cover yet) and are excluded from the rho statistics (n = 173).

Split by shape hash (SHA-256 of the nameless source, first 16 hex digits
modulo 10): 141 train, 16 validation, 23 test. Near-duplicates were removed
by shape hash before the split; two programs that differ only in names are
one shape, so a split never puts a renaming of a training program into the
test set.

## Negatives

- Conformance rejects: 343 programs with 69 distinct diagnostic codes
  (W-SYN-1 45, W-PAR-1 43, W-LEX-1 36, W-NAME-1 27, W-LEX-3 25, W-TY-1 14,
  W-INT-1 13, W-NAME-2 13, and 61 codes with fewer rows). These are the
  typed negatives: each names the rule it breaks and the specification
  clauses the test cites.
- Mutants: three token mutations (delete, duplicate, swap of one
  whitespace-separated token) per accepted program under the fixed seed.
  540 mutants: 538 rejected, 536 of them as W-SYN-1 and one each as
  W-DROP-1 and W-UNUSED-1; 2 accepted with a shape distinct from the
  parent. Known gap: a whitespace-level mutation is almost always a syntax
  error, so the mutants add many syntactic negatives and almost no typed
  ones. Version 2 should mutate at the token-class level (rename an
  identifier, swap an operator, change a literal, drop a guard) so that the
  checker's typing, ownership and refinement rules produce the negatives.

## Contamination controls

The split is by shape hash, never by surface text or path. The conformance
rejects are not mutants of the accepted rows, but 35 conformance accept
tests repeat spec examples and were collapsed as duplicates. Any model
trained on this corpus and evaluated on the RCE examples in the public
repository is evaluated in-distribution; a held-out evaluation needs
programs written after the corpus date or the test split only.

## Known gaps

- 43 of 180 programs carry an intent block; the rest are paired only with
  their own trace (a self-generated specification) or with nothing.
- No lifted programs: the lift pipeline (`rce scan --form`) is in the
  private engine, so the passive tier of the data plan is empty here.
- The emitted-size measurement excludes the runtime prelude on every
  target and counts type annotations and explicit error handling that the
  Form expresses by declaration; the gzip view in the rows is the tighter
  comparison (see RESULTS.md).
- Programs that only a package admits (standard library modules with
  dependencies, the module example) are absent.
