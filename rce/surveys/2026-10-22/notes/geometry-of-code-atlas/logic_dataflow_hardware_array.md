# Non-von-Neumann lineages as charts: logic/relational, dataflow/synchronous, actor, HDL, array, stack

Frame used throughout (from the RCE repo at `/tmp/claude-0/-home-claude/a51bc2e6-10c5-5671-9c6b-8af67db8621d/scratchpad/repos/rce`, README.md, SURFACE.md, spec/book/14 and 15): a program is a Form P=(S,E,δ,D,λ); δ is total and deterministic; D is a SHA-256 hash-chained log; in the engine profile state is relational and each rule carries a derived (never declared) `monotone` tag computed by `form::laws::calm_reason` — a rule is monotone only if it has no resolve/read/join/scan; a Form is coordination-free iff every rule is monotone; rules for different sinks run in content-hash order and "the post-state of an input event does not depend on the order in which rules for different sinks run" (spec/book/15-handler-spec-profile.md D.5). Time is a logical tick clock (TickClock.lean, VClock.lean: T24 happens-before iff vector clocks ordered). Concurrency (`par`, `for … par`) is "as if in source order"; reductions are on a normative power-of-two tree so float bits are fabric-independent (14-draft06-concurrency.md C.8).

Coordinate key for rows: **L** state layout, **E** event alphabet, **T** transition, **O** order/concurrency, **R** resource/energy, **A** trust/authority, **B** binding time, **I** intent/spec. "fix" = coordinate is nailed by the language; "free" = left to the programmer/runtime; "compact" = collapsed to a point (coordinate does not exist in the chart). Rows are compact by design; sources are given per row or per section. Where a row is from standard background knowledge without a fetched primary source, it is marked `[bg]`; the writer should treat those as needing a citation pass.

## KQ1. Which charts have deterministic concurrency by construction, and by what theorem?

### Takeaway
Five distinct mechanisms produce determinism-by-construction: (1) the synchrony hypothesis plus a causality/clock calculus (Lustre/Esterel/Signal/SCADE), (2) Kahn monotonicity over stream prefixes (KPN, SDF, FRP, Lucid), (3) one-rule-at-a-time atomicity with a static conflict scheduler (Bluespec/TRS, TLA+ actions), (4) logical monotonicity (CALM: Datalog/Bloom/Dedalus/Hydro, DBSP/Differential Dataflow), and (5) isolation plus pairwise FIFO (Erlang/actors) — which gives *per-actor* determinism only; global order remains free unless logged. RCE's Form is closest to (3) with (4) as its tag and (1) as its tick model.

### Cited Findings — rows (year; coordinates; state/time; determinism; refused; fate; FSM round-trip)

**Dataflow / synchronous / reactive**

- **Lucid** (1976, Ashcroft & Wadge). L: free (variables are infinite streams); E: compact (no events, only stream index); T: fix (equational, `fby`/`next`); O: compact (demand-driven); R/A: compact; B: static; I: equations are the spec. Time = stream index (logical). Determinism from equational semantics over streams (Kahn-style). Refused assignment and control flow. Faded as a language, survived as the ancestor of Lustre. FSM: a Lucid program with bounded `fby` history is a Mealy machine over stream index; unbounded history loses finiteness `[bg]`.
- **Lustre / SCADE** (1987 Lustre; SCADE from mid-1990s with Airbus and Merlin Gerin; KCG qualified code generator first released 1999). L: fix (flows + clocks, bounded memory); E: fix (one global tick plus clock sub-sampling); T: fix (node = step function, statically scheduled); O: **fix** (synchronous instants, topological sort — "scheduling is just topological sorting"); R: fix (bounded memory: "can be implemented in bounded memory, provided that imported functions do"); A: compact; B: static; I: observers/assertions. Time = synchronous instants with a clock calculus ("Property 2: A well clocked SCADE 6 model can execute synchronously"); causality analysis is a type system that assigns timestamps to variables and checks for cycles; "Property 3: a causal model can be compiled into statically scheduled sequential code". Refused: syntactic cycles ("By definition, a Lustre program may not contain syntactically cyclic definitions"), dynamic allocation, unbounded recursion. Saved by certification: "SCADE and KCG have been used in about hundred DO178B/C level A avionic systems all over the world"; the formal static semantics is ~100 pages, KCG ~50 KLOC; used on the A340-600 flight control, French nuclear protection, Hong Kong subway; code generator "DO178B certified". FSM round-trip: a Lustre node compiles to a single infinite loop calling a step function on a finite memory; Vélus proves "When compilation succeeds, the generated assembly is proved to be semantically equivalent to the dataflow program" (Coq/CompCert path; data-flow core without reset at the time). — [Benveniste et al. 2003, "The synchronous languages 12 years later"](https://www.cs.columbia.edu/~sedwards/papers/benveniste2003synchronous.pdf); [Colaço, Pagano, Pouzet, "Scade 6: A Formal Language for Embedded Critical Software Development", TASE 2017](https://www.di.ens.fr/~pouzet/bib/tase17.pdf)
- **Esterel** (1983 Berry & Cosserat; commercial 1998 Simulog; Esterel Technologies 1999; bought SCADE unit 2001). L: fix (signals + control state); E: fix (signals present/absent per instant); T: fix; O: **fix** (synchronous parallel `||`, deterministic by a coherence rule: "A coherence rule guarantees that an Esterel program behaves deterministically"); R: fix (finite: "all mentioned actions are assumed to take finite memory and time"); I: compact. Time = instants, reactions atomic ("a synchronous program would progress according to successive atomic reactions"). Determinism via constructive causality (the paper calls it one of the language's most significant contributions); causality checking is "costly". Refused: non-constructive programs; V4 compiler rejected some valid cyclic programs. FSM round-trip is the headline result: automata compilers (V1–V3) are fast "but none of these techniques are able to compile concurrent programs longer than about 1000 lines" (state explosion); circuit translation ("each source statement becomes a few logic gates") scales but can be "100 times slower" than automata code; Edwards' compiler gets "about half the speed of automata code". Loss: the automaton explodes exponentially in parallel composition; the circuit encoding keeps size linear but loses the explicit state graph. — [Benveniste et al. 2003](https://www.cs.columbia.edu/~sedwards/papers/benveniste2003synchronous.pdf)
- **Signal** (1980s, Le Guernic; TNI licensed early 1990s, Sildex 1993). Like Lustre but polychronous (multi-clock, relational). "Nondeterminism in Signal is due exclusively to a fixpoint equation having multiple solutions"; clock-calculus canonical form proven 1994. Refused a single master clock. Niche (Polychrony). — [Benveniste et al. 2003](https://www.cs.columbia.edu/~sedwards/papers/benveniste2003synchronous.pdf)
- **Kahn process networks** (1974, IFIP Congress). L: free per process; E: compact (tokens on FIFOs); T: fix (sequential deterministic process); O: **free but determinate**: unbounded FIFO, non-blocking write, blocking read; "Reading more tokens can only lead to writing more tokens" (monotonicity) — the network's output is the least fixpoint, independent of scheduling. R: **unbounded** — "It is an undecidable problem to test whether a KPN is strictly bounded" (Parks 1995 bounded scheduling). Refused: non-blocking reads/peeking (which reintroduce nondeterminism). FSM round-trip: a KPN is not an FSM (unbounded buffers); the SDF restriction (Lee & Messerschmitt 1987) recovers static schedules and bounded buffers `[bg]`. — [Wikipedia: Kahn process networks](https://en.wikipedia.org/wiki/Kahn_process_networks)
- **StreamIt** (2002, MIT, Thies/Amarasinghe) SDF with filters/pipelines/splitjoins; static rates give static schedule; refused dynamic rates (later added as "dynamic rate"); died with the RAW/Cell era `[bg]`.
- **Flow-Based Programming** (1970s, J. Paul Morrison, IBM); bounded-buffer KPN with "information packets"; nondeterministic merges allowed, so no global determinism; survived in NoFlo/Node-RED `[bg]`.
- **FRP: Fran** (1997 Elliott & Hudak), **Elm original** (2012 Czaplicki), **Yampa** (2002 arrowized). L: fix (behaviors/signals as functions of continuous or discrete time); O: compact (pure); R: free (Fran's space leaks killed classic FRP; Yampa's arrows fixed them); Elm dropped FRP for The Elm Architecture in 2016 (a Form: Model, Msg, update, view = (S,E,δ,λ) exactly) `[bg]`.
- **Simulink/Stateflow** (1984 Simulink; Stateflow 1990s; Embedded Coder). Fixed-step discrete solver is a synchronous tick; Stateflow is Harel statecharts; FSM round-trip: Stateflow → C via Embedded Coder is industrial routine; the paper above notes Signal/Lustre and Simulink were compared in the synchronous community; Stateflow's semantics were only formalized post hoc `[bg]` (Hamon & Rushby 2004).
- **LabVIEW** (1986, National Instruments, "G"). Structured dataflow; a node fires when all inputs present; no formal determinism theorem published by NI; survived in test/measurement `[bg]`.
- **Timely Dataflow / Naiad** (SOSP 2013; Rust `timely` 2015+). L: free per vertex; E: fix (timestamped messages); T: free (user vertex); O: **partially ordered logical time**: timestamp = epoch + one loop counter per enclosing loop, compared lexicographically, "so the order is partial"; progress tracking via pointstamps and the could-result-in relation; a notification fires "only after no further invocations" of OnRecv at ≤ t; "no local frontier ever moves ahead of the global frontier". Determinism not claimed for vertices in general (single-threaded vertices, consistent outputs). Numbers: 753 µs median global barrier on 64 machines/512 workers; PageRank 4,656 s vs 68,791 s DryadLINQ; up to 600× speedups. Fate: Microsoft Research SV closed 2014; survived as McSherry's Rust crates and Materialize (2019). — [Murray et al., Naiad, SOSP 2013](https://www.cs.princeton.edu/courses/archive/fall22/cos418/papers/naiad.pdf)
- **Differential Dataflow** (CIDR 2013 McSherry et al.). Collections vary over a lattice of times; incremental + iterative in one framework; DBSP authors say "DD's computational model is more powerful than DBSP, since it allows time values to be part of an arbitrary lattice" and DD is "the only other framework" that incrementalizes recursive queries as efficiently. — [Budiu et al., DBSP, VLDB 2023](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf)
- **Hydroflow / Hydro** (Berkeley, 2021 tech report EECS-2021-201; OOPSLA 2023 "Hydroflow: a compiler target for fast, correct distributed programs"). Dataflow IR in Rust with lattice-typed state (LVars/CALM lineage); goal: compile global programs to per-node dataflow with CALM-checked coordination. — [Hydroflow tech report](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2021/EECS-2021-201.html); [OOPSLA 2023 page](https://2023.splashcon.org/details/splash-2023-oopsla/112/Hydroflow-A-Compiler-Target-for-Fast-Correct-Distributed-Programs)
- **Flo** (POPL 2025, Laddad, Cheung, Hellerstein, Milano). "A parameterized streaming language that abstracts over dataflow operators and the underlying structure of streams"; two semantic properties, *streaming progress* and *eager execution*, "ensure that streaming outputs are deterministic and kept fresh with respect to streaming inputs"; a type system separates bounded streams (operators may block on termination) from unbounded; nested graphs with cycles; Flink, LVars and DBSP "have semantics that can be modeled in Flo". — [POPL 2025 Flo](https://popl25.sigplan.org/details/POPL-2025-popl-research-papers/9/Flo-a-Semantic-Foundation-for-Progressive-Stream-Processing)
- **Spreadsheets / Excel** (VisiCalc 1979, Lotus 1-2-3 1983, Excel 1985). L: fix (grid of cells); E: fix (cell edit); T: fix (recalc = topological evaluation of the dependency DAG); O: **fix** (acyclic by default; circular references refused unless iterative calc enabled); R: compact; B: runtime; I: compact. It is a Lustre node without clocks: one global recalculation instant; and it is the most-used dataflow language on earth; LAMBDA (2020) made it Turing-complete `[bg]`. FSM: each recalc is one δ step over the full state; no log (undo stack is a partial D).

**Concurrent / actor**

- **Erlang/OTP** (1986 Armstrong, Virding, Williams at Ericsson; BEAM 1992; AXD301 March 1998 ">1 million lines", Ericsson-reported nine-nines; Ericsson Radio ban Feb 1998; open-sourced Dec 1998; ban relaxed 2004; SMP 2006). L: fix per process (isolated heaps, "Processes are strongly isolated and share no resources"); E: fix (messages, mailbox); T: free (any function); O: **free globally, FIFO pairwise** (the pairwise ordering guarantee is in the Erlang reference manual, not on this page); R: free (per-process heaps make GC local); A: free (supervisors are the trust tree: "let it crash", supervisor receives `'DOWN'`); B: runtime (hot code loading: two module versions resident); I: compact. Determinism: none by construction — a single receive with multiple senders is a nondeterministic merge; replay requires logging the merge order (which is exactly what RCE's content-hash `select` order does, SURFACE.md). Refused: shared memory, locks, synchronous RPC as a primitive. Saved by telecom carrier-grade use and WhatsApp; Elixir (2011/2012, Valim) re-popularized BEAM. FSM round-trip: `gen_statem`/`gen_fsm` are explicit Forms per process; global system is a product of Forms with free interleaving. — [Wikipedia: Erlang](https://en.wikipedia.org/wiki/Erlang_(programming_language))
- **Occam / CSP** (CSP 1978 Hoare, CACM; occam 1983 Inmos transputer). L: fix (no shared vars across PAR, checked by compiler); E: fix (channels, rendezvous); O: free (`ALT` is nondeterministic choice); R: fix (static allocation, no recursion in occam 1/2 — same limit as Lustre); B: static. Died with the transputer (~1990s); CSP survived as the model for Go and FDR refinement checking `[bg]`. — CSP primary: [Hoare 1978 doi:10.1145/359576.359585] (cited in RCE SURFACE.md).
- **Go's CSP subset** (2009). Goroutines + channels + `select`; `select` picks uniformly at random among ready cases (spec), so non-determinism is *deliberate*; shared memory still allowed (race detector, not a type system). RCE takes the surface (`spawn`, `chan`, `select`) but resolves `select` "by the name-free content-hash order (FORM.md law 2), so concurrency replays identically" (SURFACE.md). `[bg]` for Go spec detail.
- **Akka** (2009, Scala/JVM), **Orleans** (2014 MSR, "virtual actors"). Actors with free global order; Orleans adds automatic activation/placement and a single-threaded-per-grain guarantee; neither logs for replay by default (Akka Persistence/event sourcing is the opt-in D) `[bg]`.
- **Pony** (2015, Clebsch & Drossopoulou, "Deny capabilities for safe, fast actors", AGERE 2015). Reference capabilities (iso/trn/ref/val/box/tag) prove data-race freedom at compile time; causal message ordering; no global determinism; small adoption `[bg]`.
- **Ada tasking** (1983 Ada 83 rendezvous; Ada 95 protected objects; Ravenscar profile 1997/2003 for certifiable concurrency: no dynamic tasks, no select, static priorities). Ravenscar is the actor-world analogue of SCADE's restrictions: determinism by removing the nondeterministic constructs `[bg]`.
- **Concurrent ML** (1991 Reppy): first-class synchronous events (`choose`, `wrap`, `guard`); nondeterministic choice is a value; influenced Go's select `[bg]`.
- **Reactive Manifesto / Reactors** (2013/2014): a document, not a semantics; message-driven, no determinism claim `[bg]`.
- **Structured concurrency** (Trio 2017 "nurseries", Kotlin coroutines 2018, Swift 5.5 2021 task groups): fixes the *lifetime* coordinate (a child cannot outlive its scope) but not order; RCE's `par`/`for … par`/structured spawn is this with order additionally fixed to "as if in source order" (14-draft06-concurrency.md). `[bg]`
- **Session-typed languages: Links** (2006 Cooper, Lindley, Wadler, Yallop; session types added 2014+), **SILL** (2013 Toninho, Caires, Pfenning). Protocol as type; progress + session fidelity theorems; no global determinism. RCE 0.6b reproduces this directly: `protocol` with `send/recv/offer/choose/loop`, and theorems T28g/T28a (multiparty global types, synchronous plain-merge and asynchronous full-merge, proved in Lean with 200/300 generated vectors cross-checked against the checker) — the RCE spec (14-draft06-concurrency.md, T28a/T28g rows) is the source here.
- **Esterel-style deterministic concurrency in software** (SCCharts/SCL Kiel 2014, ReactiveC, Céu 2010s): synchronous `||` with sequentially-constructive semantics; same limits as Esterel `[bg]`.

### Inferences
- Only three of these families give *global* determinism for free: synchronous (one tick, causality-checked), Kahn/SDF/DBSP (monotone stream functions), and one-rule-at-a-time with conflict-free scheduling (Bluespec, below). Actor systems give isolation, not determinism; RCE's content-hash `select` order is the missing piece that converts an actor system into a replayable Form, at the cost that the hash order is an arbitrary (but canonical) serialization, not a causal one.
- Every family that achieved certification (SCADE, Ravenscar Ada, occam) did so by *removing* the same coordinates RCE removes: dynamic allocation, unbounded recursion, nondeterministic choice.

### Gaps
- No fetched source for Erlang's pairwise FIFO guarantee text (it is in the OTP reference manual, "Erlang Processes" / "Message passing" section); Go `select` random-choice clause of the spec not fetched; Pony and SILL theorem statements not fetched; Flo's formal theorems (not just abstract) not read.

## KQ2. Bluespec guarded atomic actions and TLA+ actions vs RCE `step … on … if`: scheduling many rules per tick, conflict analysis, cost

### Takeaway
Bluespec's semantics are exactly a Form with guarded rules and nondeterministic rule choice; its 25-year lesson is that *many rules per clock* is recovered without new behaviors by static read/write-set analysis (conflict-free, sequentially composable) and a compiled scheduler, at RTL quality "comparable" to hand Verilog — and that the price is an ordering oracle (the EHR) and a non-transitive, pairwise conflict check. TLA+ actions are the same object with no scheduler at all (the model checker explores every interleaving); AWS used it since 2011 to find bugs with 35-step traces but it has no cost model.

### Cited Findings
- **TRS / Bluespec** (Hoe & Arvind TRSPEC 1999–2000; Bluespec Inc. 2003; BSV open-sourced 2020 `[bg]` for last two dates). Semantics: each operation is "a predicate plus simultaneous state updates that apply only when the predicate holds"; "the legal behaviors of the system constitute some sequential interleaving of the operations"; "any one of the enabled rules can be nondeterministically selected to update the state in one step"; hardware may run several per cycle "but it must not produce behaviors the sequential semantics forbid". — [Hoe & Arvind, "Operation-Centric Hardware Description and Synthesis", IEEE TCAD 23(9), Sept 2004](https://www.cs.ox.ac.uk/people/bernard.sufrin/personal/HANDEL/Operation-centric_hardware_description_and_synthesis.pdf)
- **Scheduling theorems (same paper):** Theorem 1 — pairwise conflict-free applicable transitions can run in one cycle by parallel composition; the result "corresponds to the sequential execution of the selected applicable transitions in any order"; "Conflict-freedom is not transitive, so every pair must be checked." Theorem 2 — sequentially composable (SC): concurrent execution need only match *one* sequential order; requires an acyclic SC-ordering; cycles broken by removing edges. Static test: CF iff no RAW/WAW between the two transitions' read and write sets. CF/SC defs restated in Memo 492: "Two rules R1 and R2 are CF if they do not read or write common state"; "SC if R1 does not write any element that R2 reads". — [Hoe & Arvind 2004](https://www.cs.ox.ac.uk/people/bernard.sufrin/personal/HANDEL/Operation-centric_hardware_description_and_synthesis.pdf); [MIT CSG Memo 492](https://csg.csail.mit.edu/pubs/memos/Memo-492/Memo492.pdf)
- **Scheduler circuit:** reference design is a priority encoder picking one enabled rule per cycle (round-robin gives weak fairness); partitioned arbitration uses connected components of the conflict graph; an enumerated group arbitrator is a lookup table indexed by the request vector whose entries are maximal cliques of the conflict-free subgraph ("may not be the maximal subset"; user input can guide). SC ordering is enforced by priority-muxed register inputs. — [Hoe & Arvind 2004](https://www.cs.ox.ac.uk/people/bernard.sufrin/personal/HANDEL/Operation-centric_hardware_description_and_synthesis.pdf)
- **Area/time/effort:** five-stage MIPS R2000 subset: TRSPEC design "competitive in size and speed to the implementation resulting from the hand-coded Verilog"; 790 lines TRSPEC vs 930 lines Verilog; eight hours vs nearly five days. Bluespec "generates RTL that is comparable in quality, i.e., area and time, to handcoded Verilog". — [Hoe & Arvind 2004](https://www.cs.ox.ac.uk/people/bernard.sufrin/personal/HANDEL/Operation-centric_hardware_description_and_synthesis.pdf); [Memo 492](https://csg.csail.mit.edu/pubs/memos/Memo-492/Memo492.pdf)
- **Ephemeral History Registers (EHR)** and performance specifications: the baseline flow "generates combinational logic for each rule's predicate (π) and each rule's state update function (δ)" and "a scheduler then chooses one of the rules whose predicate is true"; EHRs let a later rule in the per-cycle order read the value written by an earlier one, which is what makes conditionally-composed rules (e.g., bypass paths) compile. — [Memo 492, "Hardware Synthesis from Guarded Atomic Actions with Performance Specifications"](https://csg.csail.mit.edu/pubs/memos/Memo-492/Memo492.pdf)
- **TLA+** (Lamport, TOPLAS 1994 "The Temporal Logic of Actions"; book 2002; PlusCal 2009; TLC model checker) `[bg]` dates. An action is a relation on (state, next-state) — the same shape as δ with a guard. AWS: "Since 2011, engineers at Amazon Web Services (AWS) have used formal specification and model checking"; DynamoDB (launched Jan 2012) model checking found a data-loss bug whose shortest trace had 35 high-level steps; S3 fault-tolerant network algorithm: two subtle bugs. Limits stated: no modeling of emergent performance (retry storms) — "We do not yet know of a feasible way to model a real system that would enable tools to predict such emergent behavior"; no hard real-time; "Formal methods deal with models of systems, not the systems themselves"; no tool to verify or generate code at Amazon scale; Alloy "could not practically represent rich data structures", the key reason AWS moved to TLA+. PlusCal: C-style pseudo-code translated to TLA+, more productive for engineers; TLC operates at TLA+ level. — [Newcombe et al., CACM April 2015](https://cacm.acm.org/magazines/2015/4/184701-how-amazon-web-services-uses-formal-methods/fulltext)
- **Alloy** (Jackson, 2002/2006 book), **Event-B** (Abrial 2010; B-method 1996, Paris Métro line 14 1998) `[bg]`: relational logic over bounded scopes (Alloy); refinement with proof obligations and guarded events (Event-B's event = guard + action = RCE step with `if`); Rodin platform. **P language** (Microsoft 2013, Desai et al. PLDI 2013): state machines + async events, used in Windows USB stack and AWS; compiles to C and to a model checker `[bg]`.
- RCE as it stands: rules run in content-hash order *within* one input event, and D.5's claim that post-state is order-independent holds because every read/join/scan sees the pre-state — i.e., RCE chose Bluespec's "parallel composition with pre-state reads" (Theorem 1 style, all rules CF by construction because none reads another's write within a tick), not the SC/EHR style that permits intra-tick forwarding. (RCE spec/book/15-handler-spec-profile.md D.5–D.6, repo.)

### Inferences
- Bluespec answers the "many rules per tick" question with a static conflict graph and a per-cycle clique selection; RCE sidesteps it by making every rule read the entry state (all rules trivially CF), which forfeits Bluespec's SC/EHR composition (rule B sees rule A's write in the same tick). The cost Bluespec pays is a pairwise O(n²) non-transitive check and an arbitrary clique choice; the cost RCE pays is that any intra-tick dependency needs two events.
- TLA+'s failure modes (no cost model, model-vs-code gap) are precisely the two coordinates RCE's `budget`/work tables and emit-and-recheck pipeline try to close; no comparable published TLA+ energy model exists.

### Gaps
- Bluespec's own published energy/power comparisons (not just area/time) were not found in the fetched sources; Bluespec compiler scheduling paper (Esposito/Nikhil, Bluespec Inc. internal) not fetched. Event-B, Alloy, P language rows are background, uncited.

## KQ3. Synchronous languages: limits (no dynamic allocation, no recursion) — are they RCE's limits too?

### Takeaway
SCADE/Lustre's bounded-memory, statically-scheduled, no-recursion discipline is exactly what made it the most-certified language in industry (~100 DO-178B/C level-A systems); RCE already adopts the same invariants in the spec (every program finishes; loops have limits; recursion must be on smaller inputs; one region freed per step), so the limits coincide — but RCE keeps bounded recursion and per-step arenas that SCADE forbids outright, which is a certification exposure.

### Cited Findings
- SCADE 6: "can be implemented in bounded memory, provided that imported functions do"; causal models compile "into a statically scheduled sequential code"; targets "mainly C and ADA"; qualification "is based on traceability between a specification and the implementation". — [Colaço, Pagano, Pouzet 2017](https://www.di.ens.fr/~pouzet/bib/tase17.pdf)
- Esterel automata compilation limit: ~1000 lines of concurrent code before state explosion; circuit translation trades size for up to 100× speed loss. — [Benveniste et al. 2003](https://www.cs.columbia.edu/~sedwards/papers/benveniste2003synchronous.pdf)
- Validation coverage anecdote: standard functional test suites exercised only ~30% of the full state space in a Texas Instruments case study (argument for model checking over testing). — [Benveniste et al. 2003](https://www.cs.columbia.edu/~sedwards/papers/benveniste2003synchronous.pdf)
- RCE's stated invariants: "Every program finishes. Loops have limits and recursion must work on smaller and smaller parts of its input"; "one region is freed per step, so allocation cost is visible and bounded"; `par` "gives the same result as running the branches in source order". — RCE README.md, SURFACE.md, spec/book/14 (repo).

### Inferences
- The SCADE limits are RCE's limits in kind; RCE differs in degree (bounded recursion, arena allocation per step, maps and text as first-class values). Each of those is a place where a certification argument needs a bound proof rather than a syntactic exclusion.
- Esterel's automaton explosion is the warning for any RCE "emit to FSM" target: the product of `par` branches must be emitted as a circuit/structured step, not an explicit state graph.

### Gaps
- No direct citation fetched for "no recursion" as a stated Lustre rule (it is a property of Lustre v4/SCADE node instantiation being static; the TASE paper implies it via bounded memory). Vélus's current coverage (reset, state machines) after 2017 not checked.

## KQ4. Datalog's monotone/stratified-negation line vs RCE's derived monotone tag; IVM (DBSP, Differential Dataflow) as the model for "the log is the database"

### Takeaway
CALM (conjectured PODS 2010, proved Ameloot et al. JACM 2013/TODS 2016) says coordination-free consistency ⇔ monotonicity; RCE's tag is a sound-not-complete syntactic approximation of that semantic property. DBSP (VLDB 2023 best paper) gives the algebra RCE needs for "the log is the database": Q^Δ = D∘Q∘I over Z-sets, with a chain rule that incrementalizes any composition, including stratified recursion via nested streams — and it is formalized in Lean (5K lines), the same prover RCE uses.

### Cited Findings — rows

- **Prolog** (1972 Colmerauer & Roussel; Warren DEC-10 compiler 1977; WAM 1983). L: free (terms, no mutable state except assert/retract); E: compact (queries); T: fix (SLD resolution, depth-first, left-to-right); O: **fix sequential** (the cut `!` and clause order make it operational, not declarative); B: runtime; I: free (Horn clauses are the spec but operational completeness is lost). Refused: types, mutable variables. Killed in industry by Fifth Generation collapse (early 1990s); saved by SWI-Prolog and ISO 1995 `[bg]`. FSM: no natural Form; assert/retract is an unlogged δ.
- **Datalog** (term coined ~1986; Ceri, Gottlob, Tanca 1989 survey). L: **fix relational**; E: compact (EDB facts); T: fix (immediate consequence operator, least fixpoint); O: **compact** (order-independent by monotonicity); negation only stratified. "Datalog and Soufflé: negation must be stratifiable, and evaluation is a fixpoint that ends when no new facts appear." — RCE spec/book/16-host-contract.md G-5 (repo). Revived 2000s (Semmle/CodeQL, LogicBlox ~2010, Soufflé 2016, Datomic 2012, Rel/RelationalAI). FSM round-trip: Datalog → semi-naïve fixpoint loop is exactly a Form that iterates δ until a fixpoint; the loss is that the *step* count is unobservable to the program (no notion of event order) — Dedalus adds it.
- **Dedalus** (Berkeley tech report EECS-2009-173, Dec 2009; Datalog Reloaded 2011). "Reduces to a subset of Datalog with negation, aggregate functions, successor and choice"; time is an explicit attribute; the three rule kinds (deductive, same timestamp; inductive `@next`, successor; asynchronous `@async`, chosen via `choice`) `[bg for the names]`; buys "mutable state and asynchronous processing and communication, given a declarative foundation"; "stratified monotonic reasoning with negation over time". — [Alvaro et al., EECS-2009-173](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2009/EECS-2009-173.html). This is the closest existing chart to RCE's (S relational, E = facts at time t, δ = next rules, D = the time-indexed relations themselves).
- **Bloom** (CIDR 2011 "Consistency Analysis in Bloom: a CALM and Collected Approach"). Data-centric, rule-based; non-monotone operators (anti-join, set minus) are visible in syntax; CALM static analysis certifies convergence; Blazes adds coordination where confluence cannot be proven; lattice types (CRDT-like) in Bloom^L. — [Hellerstein & Alvaro, Keeping CALM (arXiv 1901.01930 / CACM 2020)](https://ar5iv.labs.arxiv.org/html/1901.01930); [Bloom CIDR 2011 pdf](https://dsf.berkeley.edu/papers/cidr11-bloom.pdf)
- **CALM theorem:** "A program has a consistent, coordination-free distributed implementation if and only if it is monotonic." Conjecture at PODS 2010 keynote; proved by Ameloot et al. (JACM 2013, relational transducers; TODS 2016). Monotone: S ⊆ T ⇒ P(S) ⊆ P(T); allowed operators selection, projection, intersection, join, transitive closure; excluded set difference, universal quantification, ¬∃. Non-monotone examples: distributed garbage collection ("previous 'answers' may need to be retracted!"), bare assignment, shopping-cart deletes (fix: separate grow-only sets). "CALM is not constructive". — [Keeping CALM](https://ar5iv.labs.arxiv.org/html/1901.01930)
- **RCE tag vs CALM:** RCE's rule is "monotone only when it has no resolve, no read, no join and no scan", "conservative (sound, not complete): a join against an insert-only relation would be monotone in principle, but the profile does not prove insert-only". — RCE spec/book/15-handler-spec-profile.md D.5 (repo). Bloom's analysis is finer: it classifies *operators* (join is monotone; anti-join/minus are not), so RCE's refusal of all joins is strictly more conservative than the literature.
- **Soufflé** (2016, Oracle Labs → open source; compiles Datalog to parallel C++), **LogicBlox** (~2010; LogiQL; acquired by Infor 2017), **Flix** (2016 Madsen; Datalog over lattices, first-class constraints), **Rel** (RelationalAI, 2020s) `[bg]`.
- **miniKanren** (2005 Byrd/Friedman; "The Reasoned Schemer"). Relational, complete interleaving search (no cut), so order-independent *results* but order-dependent *enumeration*; small embeddable core (~50 lines) `[bg]`.
- **Mercury** (1995 Somogyi, Henderson, Conway). Prolog with modes, determinism declarations (det/semidet/multi/nondet) checked by the compiler — the one logic language that makes determinism a *type*; purity enforced; niche `[bg]`.
- **SQL** (SEQUEL 1974; ANSI 1986; recursive CTEs SQL:1999; MGQL/GQL 2024). Relational algebra is monotone except `EXCEPT`/`NOT IN`/aggregates; recursive CTEs are linear-recursion Datalog with semi-naïve evaluation; non-monotone recursion is implementation-defined. "GQL, ISO/IEC 39075:2024, published 12 April 2024"; MGQL mechanizes a read-only GQL fragment in Lean 4 (~23,600 lines, no sorry). — RCE spec/book/16 (repo, which cites Deutsch et al. GPML and Thimmaiah et al. OOPSLA 2026).
- **Verse** (Epic, 2023; Augustsson, Peyton Jones et al., "The Verse Calculus", ICFP 2023). Functional-logic: logical variables, choice `|`, `one`/`all`, deterministic lenient evaluation; rewrite rules prove confluence of the core; replaces Prolog's search order with a deterministic, order-respecting enumeration `[bg]`.
- **DBSP** (VLDB 2023; Budiu, Chajed, McSherry, Ryzhyk, Tannen; Feldera). Z-sets: "functions with finite support from A to Z"; D(s)[t] = s[t] − s[t−1], I(s)[t] = Σ_{i≤t} s[i], inverses (Thm 2.20); Q^Δ = D∘Q∘I; chain rule: "to incrementalize a composite query you can incrementalize each sub-query independently" (Algorithm 4.6); linear ops (select, project, group) satisfy Q^Δ = Q (Thm 3.3); bilinear join: (a×b)^Δ = Δa×b + a×Δb + Δa×Δb (Thm 3.4); recursion via a feedback loop with z⁻¹, nested streams SS_A = N→(N→A); the resulting circuit "implements semi-naïve evaluation"; covers "monotonic and non-monotonic recursion"; Rust implementation passes "all 7 million SQL Logic Tests"; Lean formalization ~5K lines. — [Budiu et al. VLDB 2023](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf); [arXiv 2203.16684](https://arxiv.org/abs/2203.16684); [Best paper note](https://feldera.com/blog/Best-Research-Paper-VLDB-2023)

### Inferences
- "The log is the database" is literally DBSP's I operator: the state S_t = I(D)[t] where D is the stream of Z-set deltas; a query over S maintained from D is Q^Δ. RCE's RCEdb indexes "are deterministic folds written in RCE" (README) — i.e., they are I∘Q evaluated non-incrementally; DBSP is the proof that they can be made incremental mechanically, with a Lean artifact to port.
- Dedalus's `@next`/`@async` split maps onto RCE's event kinds: `@next` = TICK, `@async` = IN_<source> with a nondeterministic arrival that RCE pins by logging. Dedalus leaves arrival to `choice`; RCE's D makes the choice durable.
- The CALM literature classifies by operator; RCE's tag classifies by access kind. Adopting Bloom's finer classification (join monotone if both inputs insert-only) would require RCE to prove insert-only relations, which its own spec flags as the missing piece.

### Gaps
- Dedalus rule-type names/semantics not confirmed from the full PDF (abstract only). Verse's confluence theorem statement not fetched. Mercury determinism categories cited from memory. Ameloot's exact JACM theorem statement not fetched (only as cited by Hellerstein/Alvaro).

## KQ5. Array languages: APL's one-glyph-per-primitive as a minimal-entropy surface; token efficiency; why niche

### Takeaway
Iverson's 1979 criteria (ease of expression, suggestivity, subordination of detail, economy, amenability to formal proofs) are a surface-entropy argument; APL's economy comes from "any symbol to represent both a monadic function… and a dyadic function", no precedence ("All functions are treated alike"), and strict right-to-left. The family stayed niche for reasons the Form explains: it fixes L (rectangular arrays) and compactifies E and O entirely, so it has no native notion of event, log, or concurrency.

### Cited Findings — rows
- **APL** (notation 1957–62, "A Programming Language" 1962; APL\360 1966; Turing Award 1979). Good notation: "Ease of expressing constructs arising in problems", "Suggestivity", "Ability to subordinate detail", "Economy", "Amenability to formal proofs". Economy: letting "any symbol to represent both a monadic function (i.e. a function of one argument) and a dyadic function" (as with minus), "an economy of symbols, not of functions". No precedence: "the right argument of a function is the value of the entire expression to its right… All functions are treated alike, and there are no rules of precedence"; "Unambiguous executability of the notation introduced remains important"; executable statements let a computer "be used to identify errors" in proofs. — [Iverson, Notation as a Tool of Thought, CACM 1980 (1979 Turing lecture)](https://www.dcs.gla.ac.uk/~wpc/grcs/a1979-iverson.pdf). Coordinates: L fix (shape + ravel: "An array is a rectangular collection of data… defined by a shape… and a ravel" — BQN spec as read in RCE spec/book/16 TU-1); E compact; T free (any expression); O compact (implicit data parallelism, no ordering concept); R compact; B runtime (dynamic rank/shape); I compact. Refused: scalar loops, control flow (originally), ASCII. Killed by the keyboard and by the lack of a module/type story; survived in finance (K/q), Dyalog, and as NumPy's grammar.
- **J** (1990, Iverson & Hui; ASCII digraphs; tacit programming/trains), **K/q** (1993 Whitney; kdb+ 1998/2003; q is K with a SQL-like relational layer — the one array language that *added* a relational state coordinate and thereby conquered a market, finance tick databases) `[bg]`.
- **Fortran** (1957; array semantics Fortran 90, 1991; `DO CONCURRENT` 2008). Whole-array expressions have Kahn-like value semantics (RHS fully evaluated before assignment), so aliasing-free; `DO CONCURRENT` fixes O to "any order" `[bg]`.
- **NumPy** (2005/2006 Oliphant, merging Numeric 1995 and Numarray). APL semantics with Python syntax; broadcasting rules; mutable views alias, so value semantics are lost `[bg]`.
- **Futhark** (PLDI 2017 Henriksen et al.). Pure, "All arrays must be regular, meaning that, all rows of an array must have the same shape"; where shape cannot be verified statically, Futhark inserts dynamic checks; nested parallelism flattened to GPU; in-place updates via uniqueness types. RCE TU-2 "takes the regularity rule and refuses instead of checking dynamically". — RCE spec/book/16 TU section citing Futhark (repo). Coordinates: O fix (data-parallel, deterministic), R partially fix (no recursion, no allocation inside kernels) — the same SCADE-shaped restrictions.
- **Halide** (PLDI 2013 Ragan-Kelley et al.), **TVM** (2018), **Triton** (2019/2021 OpenAI). Algorithm/schedule separation: the *what* is a pure Form (functional definition over an index domain), the *where/when* (tiling, vectorization, fusion, placement) is a separate schedule that cannot change results. This is a two-chart product: one chart fixes T and compactifies O; the other fixes O/R and compactifies T. RCE's HC-12/TU-6 ("Placement… keys the fabric cost table by (pure operation, element type, shape). Choosing a fabric changes cost only") is the same separation, with the result bits pinned. — RCE spec/book/16 TU-6 (repo); Halide `[bg]`.
- **Dex** (Paszke et al. 2021, arXiv 2104.05372): arrays typed `n=>a` over typed index sets; the index domain is part of the type (basis of RCE TU-2/TU-3). — RCE spec/book/16 (repo).

**Stack / concatenative**
- **Forth** (1970 Moore; Forth-79, Forth-83; ANS Forth 1994 (X3.215-1994); Forth 2012). L: **fix** (two stacks + dictionary); E: compact; T: fix (word = function from stack to stack); O: compact (sequential); R: fix (tiny: whole systems in KB; word count is the cost); A: compact (no protection); B: **free** (the compiler is in the language: `IMMEDIATE`, `CREATE DOES>`, compile-time words); I: compact. Refused: syntax, types, a parser. Saved by embedded/boot firmware (Open Firmware IEEE 1275-1994, Sun/Apple boot) and by its size; killed in applications by lack of types and structure `[bg]`. FSM round-trip: a Forth word is a δ over (data stack, return stack, memory); the dictionary extension at runtime makes E and T open-ended, so a Forth program is a Form whose δ is itself in S.
- **PostScript** (1982 Adobe, Warnock & Geschke; Level 2 1991; PDF 1993 removed programmability). Forth-like stack language that fixed I (page description) — PDF is PostScript with B and T compactified (no loops), traded Turing-completeness for predictability; the most successful "refusal" in the lineage `[bg]`.
- **Joy** (2001 von Thun): pure concatenative, functions compose by juxtaposition, algebra of programs (concatenation = composition), quotations as first-class; theory language, no adoption `[bg]`. **Factor** (2003 Pestov): typed-ish concatenative with an optimizing compiler; small community `[bg]`.

### Inferences
- APL's "minimal-entropy surface" is real but is purchased by compactifying E, O, A and I: there is nothing to say about events, order, trust, or intent in the notation, which is why the one array language that won a market (q) did so by bolting on relations (tables, keyed joins, time-series `aj`), i.e., by re-opening the state-layout coordinate toward Codd.
- Token efficiency (one glyph = one primitive, no precedence) is directly relevant to an LLM-authored surface only if the glyph set is in the tokenizer; APL glyphs are multi-byte and rare, so "fewer characters" ≠ "fewer tokens" (no source measures this; see Gaps).
- The Halide/TVM schedule separation is the array world's version of Bluespec's "semantics vs scheduler" split; both say: pin the meaning in one chart, let cost live in another.

### Gaps
- No source found measuring LLM token counts for APL/J/K vs Python; no HOPL-grade citation fetched for Forth (Rather, Colburn, Moore, "The evolution of Forth", HOPL-II 1993) or K/q history; Halide/TVM/Triton citations from background.

## KQ6. Hardware languages: synthesis gives joules per op; what the HDL world knows about cost that software does not

### Takeaway
HDL cost knowledge is structural: (a) cost is a property of the *synthesized netlist*, not the source, so every HDL flow reports area/timing/power after a deterministic lowering; (b) one-rule-at-a-time semantics (Bluespec) proved that an abstract Form can be lowered to that netlist at hand-written quality; (c) the discipline that makes this possible is the one RCE has imported for software: no dynamic allocation, static schedule, explicit clock. Energy per operation is obtained from the netlist (switching activity × capacitance × V²) by standard tools; the fetched Bluespec sources report area and time but not energy.

### Cited Findings — rows
- **Verilog** (1984 Gateway; IEEE 1364-1995; SystemVerilog IEEE 1800-2005), **VHDL** (1983 DoD VHSIC; IEEE 1076-1987). L: fix (registers, wires, modules); E: fix (clock/posedge, signal events); T: fix per `always`/process block; O: **free within a delta cycle** (simulation is event-driven with delta cycles; synthesis requires a synthesizable subset and a single clock domain per register; blocking vs non-blocking assignment races are the canonical nondeterminism); R: **the output** (synthesis reports area, fmax, power); A: compact; B: static (elaboration time generates); I: assertions (SVA, PSL). Refused by synthesis: `#delay`, dynamic memory, recursion, unbounded loops — exactly the SCADE list. FSM round-trip: RTL ↔ Mealy/Moore FSM is lossless for the synchronous subset (every register is state, every combinational cone is δ); loss only in simulation-only constructs `[bg]`.
- **Bluespec** (see KQ2): rules → RTL with a compiled scheduler; "comparable in quality, i.e., area and time, to handcoded Verilog"; 8 hours vs 5 days design time. — [Hoe & Arvind 2004](https://www.cs.ox.ac.uk/people/bernard.sufrin/personal/HANDEL/Operation-centric_hardware_description_and_synthesis.pdf); [Memo 492](https://csg.csail.mit.edu/pubs/memos/Memo-492/Memo492.pdf)
- **Chisel** (2012 Berkeley, Scala-embedded; FIRRTL IR 2017; RISC-V Rocket/BOOM), **SpinalHDL** (2016, Scala), **Clash** (2009–, Haskell → VHDL/Verilog; circuits as functions over `Signal` streams, i.e., Lustre in Haskell types), **Amaranth** (nMigen 2018 → Amaranth 2021, Python): all are *generators* that fix B to "host-language runtime = elaboration time" and emit synthesizable RTL; none changes the semantic coordinate of Verilog — they move the metaprogramming coordinate into a typed host. Clash is the exception in making the synchronous-dataflow semantics first-class (Signal a ≅ Lustre flow) `[bg]`.
- **HLS C** (Vivado HLS 2012/Vitis HLS; Catapult; LegUp 2011): C with pragmas; the compiler infers a schedule (initiation interval, pipelining); refused: pointers to dynamic memory, recursion, unbounded loops; the schedule is the Halide-style second chart over a sequential first chart `[bg]`.
- Energy/area as first-class in the Form: RCE's HC-12/TU-6 cost table keyed by (operation, element type, shape) and its `work(m,n,k)` complexity-class table (14-draft06-concurrency.md C.6, "work is monotone") are the software analogue of a synthesis report; the HDL lesson is that the report is only trustworthy because lowering is deterministic and the source cannot allocate.

### Inferences
- The HDL world's cost model is credible because the *semantics are fixed before cost is measured*; software cost models fail because the runtime (allocator, GC, scheduler) is a hidden nondeterministic second program. RCE's "one region freed per step" and normative reduction tree are the steps that make a synthesis-style cost report possible; the remaining gap is a per-fabric joules table, which HDL tools get from switching activity and RCE would have to get from measurement.
- Bluespec is the strongest existence proof for RCE's thesis: a guarded-rule Form compiled to hardware at hand-coded quality, with determinism preserved by a static conflict analysis rather than by runtime locks.

### Gaps
- No fetched source gives Bluespec (or any HDL) *energy* per operation vs hand Verilog; only area/time. Chisel/FIRRTL, Clash, Amaranth, HLS rows are background without fetched citations. No source on Verilog delta-cycle nondeterminism was fetched (it is in IEEE 1364 §9/11 scheduling semantics).

## Cross-cutting summary for the atlas (uncited synthesis)

- Charts that **fix O to a single global instant**: Lustre, Esterel, Signal, Simulink fixed-step, Excel recalc, synchronous RTL. Determinism by causality/acyclicity check. FSM round-trip exact; automaton explosion under parallel composition (Esterel ~1000 lines).
- Charts that **free O but make it unobservable**: KPN/SDF/StreamIt/Lucid/FRP (Kahn monotonicity), Datalog/Bloom/Dedalus/Hydro (CALM monotonicity), DBSP/Differential Dataflow (linear algebra over Z-sets/lattice times), APL/Futhark/Halide (data-parallel purity). Determinism by a monotonicity or purity theorem.
- Charts that **free O and log it**: Bluespec (one-rule-at-a-time with scheduler), TLA+ (model checker enumerates), Erlang with event sourcing, RCE (content-hash order + D). Determinism by serialization.
- Charts that **free O and do not log**: Erlang/Akka/Orleans/Go/Ada default; these are the ones that need RCE's D to become Forms.
- The two coordinates no lineage here fixes well are **A (trust/authority)** — only Erlang supervisors and Pony capabilities touch it — and **I (intent)** — only TLA+/Event-B/Alloy specs, SCADE observers, and Prolog's declarative reading touch it. RCE's `intent`/`example` blocks and supervisor trees occupy both.
