# ALGOL / systems-programming lineage — one chart of the atlas (for RCE design)

Notation for the 8 intrinsic coordinates: **S** state layout, **E** event alphabet, **δ** transition, **O** order/concurrency, **R** resource/energy, **T** trust/authority, **B** binding time, **I** intent/spec. For each language: **Fix** = author must write it down; **Free** = left to compiler/runtime/machine; **Pt** = compactified to a point (the language has no word for it). "FSM-in" = cheapest known translation into a first-order state machine; "FSM-out" = cheapest translation from one back into idiomatic code. Dates from Wikipedia unless a primary source is given. Sources marked [not re-fetched] are URLs I know but did not open in this session; treat as pointers to verify, not as confirmed quotations.

Frame source: RCE README and SURFACE.md in the repo clone (`/tmp/claude-0/-home-claude/a51bc2e6-10c5-5671-9c6b-8af67db8621d/scratchpad/repos/rce`), which already lists what RCE takes from Rust, Zig, Go, Swift and Python; `spec/LANGUAGE-REVIEW.md` (2026-10-12) covers Rust, Go, Python, Mojo, Zig, Haskell with measured costs. This note does not repeat that review; it fills in the rest of the lineage and the geometry.

## Key question 0: one row per language (schema: year; Fix/Free/Pt; memory; concurrency; binding-time; refused; killed/saved; FSM-in; FSM-out; round-trip loss)

### Takeaway
Every language in the family fixes **S** and **δ** in the author's hand, frees **O** (nondeterministic threads are the default everywhere except Ada Ravenscar, Go's channel discipline and Swift 6 actors), compactifies the **log** and **I** to a point (no language in the family makes the event log a first-class artefact; only Ada 2012/SPARK, D and Austral give **I** a syntax), and treats **R** as bytes and time, never energy.

### Cited Findings (rows)

- **ALGOL 60 (1960).** Fix S (block-scoped, stack discipline), δ (structured statements); Free O (no concurrency word), R (no storage model in the Report), B (call-by-name is a thunk = late binding); Pt E (no I/O in the Report), I, T. Memory: stack of activation records, no heap. Concurrency: none. Metaprogramming: none (call-by-name is the closest). Refused: I/O was deliberately left out of the Report. Killed: no I/O, no standard implementation; saved as the grammar (BNF) and block-structure ancestor of everything below — [Wikipedia: ALGOL 60](https://en.wikipedia.org/wiki/ALGOL_60). FSM-in: Reynolds' defunctionalization of thunks (1972) — [Reynolds, Definitional Interpreters](https://dl.acm.org/doi/10.1145/800194.805852). Round-trip: call-by-name has no C equivalent; translation to C must defunctionalize each thunk into a closure struct (loss: the Jensen's-device idiom).
- **ALGOL 68 (1968).** Fix S (orthogonal modes, refs), δ, B (two-level van Wijngaarden grammar fixes static semantics in the grammar itself); Free O (`par` clauses and semaphores exist but are unordered), R (heap with GC permitted). Pt I, T. Memory: stack + GC'd heap. Concurrency: `par` + semaphores. Refused: nothing; the opposite problem. Killed: the 1968 Minority Report (Dijkstra, Hoare, Wirth et al.) rejected the Report as too complex; Wirth left to design Pascal — [Wikipedia: ALGOL 68](https://en.wikipedia.org/wiki/ALGOL_68). FSM-in/out: no production evidence found. Round-trip loss: orthogonality (coercions, united modes) has no C target.
- **Pascal (1970).** Fix S (records, variants, strong nominal types), δ; Pt O (no concurrency), T, I; Free R (`new`/`dispose` manual). Memory: manual heap. Concurrency: none (Concurrent Pascal 1975 added monitors). Binding time: none. Refused: separate compilation, variable-length arrays (Kernighan's 1981 critique lists these as fatal for systems work) — [Kernighan, "Why Pascal is Not My Favorite Programming Language"](https://www.lysator.liu.se/c/bwk-on-pascal.html). Killed for systems use by that list; saved in teaching and in Delphi/Turbo Pascal commercially — [Wikipedia: Pascal](https://en.wikipedia.org/wiki/Pascal_(programming_language)). FSM-in: p-code (1973) is the first widely deployed bytecode VM = a fixed-alphabet machine; this is the cheapest "into a machine" path. Round-trip loss to C: variant records lose their discriminant check; nested procedures lose static links.
- **Modula-2 (1978) / Modula-3 (1988).** M2: Fix S, δ; **Fix O as coroutines** (`TRANSFER`/`IOTRANSFER` in `SYSTEM`); Free R (manual); Pt I. M3: adds GC, exceptions, objects, `UNSAFE` modules (first language to fix **T** as a module-level keyword), threads as a library — [Wikipedia: Modula-3](https://en.wikipedia.org/wiki/Modula-3). Refused (M3): multiple inheritance, operator overloading. Killed: DEC SRC/Olivetti closure and Java (1995) absorbed its niche; saved as the design input to Java/C#/Python (the Modula-3 report is cited by Python's class design) — [Wikipedia: Modula-3](https://en.wikipedia.org/wiki/Modula-3). FSM-in: M2 coroutines are stackful; they do not lower to first-order state machines without CPS. Round-trip loss to C: M3 `UNSAFE` and GC root tracking disappear.
- **Oberon (1987).** Fix S, δ; Pt O (single-process system; event loop is the OS), T, I; Free R (GC). Memory: GC. Concurrency: none in the language; the Oberon System is a single-threaded event loop — [Wikipedia: Oberon](https://en.wikipedia.org/wiki/Oberon_(programming_language)). Refused: almost everything; Wirth's 1995 "A Plea for Lean Software" is the family's canonical restraint rationale — [Wirth 1995, IEEE Computer](https://cr.yp.to/bib/1995/wirth.pdf) [not re-fetched]. Killed: no industrial adopter; saved as proof that a full OS+compiler fits in ~10k lines (Project Oberon). FSM-in: the Oberon System *is* a first-order event loop (the cheapest translation in the family: the OS calls handlers on events).
- **Ada (1983; 95, 2005, 2012, 2022) / SPARK (1988; SPARK 2014).** Fix S (ranged scalar types, representation clauses fix layout bit-for-bit), δ, **O (rendezvous tasking, protected objects; Ravenscar profile fixes a static task set, no dynamic tasks, no `select` — the only mainstream tasking subset designed to be statically schedulable)**, **I (Ada 2012 `Pre`/`Post`/`Type_Invariant` aspects; SPARK proves them)**, R (`pragma Restrictions`, no-heap profiles). Free B (generics are instantiated explicitly, no CTFE). Memory: access types with storage pools; SPARK forbids access types by default (ownership added in SPARK 2019 via Rust-like rules) — [AdaCore: About SPARK](https://www.adacore.com/about-spark) [not re-fetched]; [SPARK 2014 Reference Manual](https://docs.adacore.com/spark2014-docs/html/lrm/) [not re-fetched]. Refused: the Ada 83 Rationale documents why implicit conversions, untyped pointers and preprocessing were refused — [Ada 83 Rationale](http://archive.adaic.com/standards/83rat/html/Welcome.html) [not re-fetched]. Killed in general computing by cost of compilers and the 1980s DoD-mandate backlash (mandate dropped 1997); saved in avionics/rail/defense — [Wikipedia: Ada](https://en.wikipedia.org/wiki/Ada_(programming_language)). FSM-in: Ravenscar + SPARK gives a bounded, statically enumerable task set, which is as close as the family gets to a finite machine by construction. Round-trip to C: representation clauses, ranges and contracts are lost (GNAT can emit C via CCG with restrictions — [not re-fetched]).
- **C (1972; K&R 1978; ANSI 1989; C99, C11, C17, C23).** Fix S (object layout modulo padding, integer widths per ABI), δ (but partial: undefined behavior makes δ undefined on a large subset of inputs); Free O (evaluation order of operands unspecified; threads since C11 with a data-race-is-UB memory model), R (lifetime is the author's convention, not the language's), B (preprocessor = textual binding before parse); Pt T (no authority concept; "trust the programmer" is a stated principle in the C99 Rationale) — [C99 Rationale v5.10](https://www.open-std.org/jtc1/sc22/wg14/www/C99RationaleV5.10.pdf) [not re-fetched], I. Memory: manual. Concurrency: C11 threads/atomics. Metaprogramming: preprocessor only. Refused: bounds checks, a runtime, a defined behavior for overflow. Killed/saved: saved by Unix; now under policy pressure — the US ONCD report (2024-02-26) asks for memory-safe languages — [ONCD press release](https://www.whitehouse.gov/oncd/briefing-room/2024/02/26/press-release-technical-report/) [not re-fetched]. Google's figures (0.2 vs ~1,000 memory-safety vulns per MLoC Rust vs C/C++) are quoted with caveats in RCE's own LANGUAGE-REVIEW.md Part 1. FSM-in: Duff's device / Protothreads (Dunkels 2006) turn a C function with blocking points into a `switch` state machine using line numbers as states — [Protothreads, SenSys 2006](https://dl.acm.org/doi/10.1145/1182807.1182811) [not re-fetched]; Tatham's "Coroutines in C" — [Tatham](https://www.chiark.greenend.org.uk/~sgtatham/coroutines.html) [not re-fetched]. FSM-out: trivial (C *is* the family's assembly). Round-trip loss C→Rust: c2rust emits `unsafe` Rust with raw pointers; ownership is not recoverable mechanically — [c2rust](https://github.com/immunant/c2rust) [not re-fetched]. Formal: CompCert (verified compiler, Coq) — [compcert.org](https://compcert.org/) [not re-fetched]; Frama-C (ACSL, WP/EVA) — [frama-c.com](https://frama-c.com/) [not re-fetched]; pointer provenance is still being specified (WG14 TS 6010) — [N3005](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3005.pdf) [not re-fetched].
- **C++ (1985; ISO 1998, 11, 14, 17, 20, 23, 26 in progress).** Fix S, δ, **B (templates are a Turing-complete compile-time language; `constexpr`/`consteval` add a second, typed one)**; Free O (C++11 memory model, threads), R (RAII fixes release *points* but not budgets); Pt T (no `unsafe` marker; everything is unsafe), I (Contracts were pulled from C++20 and re-entered C++26 as P2900). Memory: manual + RAII + smart pointers. Concurrency: threads, atomics, C++20 coroutines, executors (P2300 `std::execution` for C++26). Metaprogramming: templates (Turing-complete — Veldhuizen 2003) + constexpr. Refused: a GC (C++11's GC hooks were removed in C++23), ABI breaks. Killed/saved: Stroustrup's "Remember the Vasa!" (P0977, 2018) warns the committee against feature pile-up — [P0977R0](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2018/p0977r0.pdf) [not re-fetched]; C++26 converts some UB to "erroneous behavior" (P2795) — [P2795](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/p2795r5.html) [not re-fetched]. FSM-in: **C++20 coroutines are compiler-lowered to a heap-allocated frame plus resume/destroy function pointers; the frame is the state, `co_await` points are the states** — [cppreference: Coroutines](https://en.cppreference.com/w/cpp/language/coroutines) [not re-fetched]. FSM-out: none mechanical. Round-trip loss C++→C: templates must be monomorphized, exceptions become `setjmp`/`longjmp` or error codes (Cfront did this 1983–1993).
- **D (2001; D2 2007).** Fix S, δ, B (CTFE: any D function can run at compile time; `static if`, mixins), I (`in`/`out`/`invariant` contracts are built in, 2001); Free O (threads with thread-local-by-default globals, `shared`), R (GC by default). Pt T partly (`@safe`/`@trusted`/`@system` attributes — the first "three-level trust" in the family). Memory: GC, with `-betterC` (2017) removing the runtime — [D BetterC spec](https://dlang.org/spec/betterc.html) [not re-fetched]; [D GC spec](https://dlang.org/spec/garbage.html) [not re-fetched]. Concurrency: threads, `std.concurrency` message passing, fibers. Refused: nothing in principle (D is additive). Killed: GC-by-default kept systems adopters away and D1/D2 and Phobos/Tango splits (2007–2012) fractured the community — [Wikipedia: D](https://en.wikipedia.org/wiki/D_(programming_language)). FSM-in: D fibers are stackful (no lowering); no production state-machine lowering found. Round-trip loss to C: contracts, CTFE results fine (constants), GC roots lost.
- **Go (2009; 1.0 2012-03; generics 1.18 2022-03).** Fix S (zero values, no uninitialized state), δ, **O partially (goroutines + channels + `select`; the Go memory model fixes happens-before only for synchronized accesses)** — [Go memory model](https://go.dev/ref/mem) [not re-fetched]; Free R (GC, no lifetimes), B (no macros, no CTFE; `go generate` is external). Pt T (no `unsafe` block; `unsafe` is a package), I. Memory: GC (concurrent, non-generational). Concurrency: CSP-style, stackful goroutines (M:N scheduler), **not** state machines. Metaprogramming: none by design. Refused: documented through the proposal process — accept/decline/design-doc, reviewed weekly by a Go-team group, escalation to three architects then an arbiter; language changes must "address an important issue for many people, have minimal impact on everyone else," and never break the Go 1 compatibility promise — [golang/proposal](https://github.com/golang/proposal) (fetched 2026-10-22). Generics were refused for ~12 years then accepted in 1.18 — [Wikipedia: Go](https://en.wikipedia.org/wiki/Go_(programming_language)). Saved by Google backing, the cloud (Docker 2013, Kubernetes 2014) and the compat promise — [Go 1 compatibility](https://go.dev/doc/go1compat) [not re-fetched]. FSM-in: none in the language; goroutines are the *opposite* choice (stack switching). FSM-out: a state machine becomes a goroutine loop over a channel (idiomatic). Round-trip loss Go→C (cgo): goroutine scheduling, GC, panics; the Discord GC-pause incident in LANGUAGE-REVIEW.md is the documented cost of Free-R.
- **Zig (2016; 0.15 2025).** Fix S, δ (with "Illegal Behavior" as a named, checkable class of UB in safe modes), **R (every allocating function takes an allocator; allocation failure must be handled)**, B (`comptime` = partial evaluation of ordinary Zig; lazy, order-independent top-level); Free O (threads; async was removed in 0.11 (2023) and is being re-added as an `Io` interface in 0.16 — [Zig 0.11 release notes](https://ziglang.org/download/0.11.0/release-notes.html) [not re-fetched]; [Zig devlog 2025](https://ziglang.org/devlog/2025/) [not re-fetched]); Pt I. The overview page states: "There is no hidden control flow, no hidden memory allocations, no preprocessor, and no macros," and "all control flow managed exclusively with language keywords" — [Zig overview](https://ziglang.org/learn/overview/) (fetched 2026-10-22). Memory: manual, allocator-parameter discipline. Concurrency: threads; async in flux. Refused: operator overloading, exceptions, hidden allocation, macros (same page). Saved by Bun (2022) and TigerBeetle (2020–) as flagship users [opinion: adoption rests on a few large users; no 1.0]. FSM-in: the removed async (0.10) lowered `async fn` to frames = state machines; the new design puts the state in the `Io` implementation. Round-trip loss Zig→C: comptime is fully evaluated (no loss); error unions and defers become code.
- **Odin (2016).** Fix S (zero-init default, data separate from behavior), δ, R (implicit `context` carries the allocator); Free O (threads only; "no concurrency model or guidance" in the FAQ), B (`when`, `#assert`, parametric polymorphism, no macros); Pt T, I. Refused, per FAQ: exceptions, RAII/constructors/destructors, capturing closures ("would need automatic memory management, which runs counter to Odin's core philosophy"), methods, operator overloading, implicit conversions, `++`, a package manager ("never"), 8/16-bit targets; the language is "effectively done," no public roadmap ("roadmaps are marketing") — [Odin FAQ](https://odin-lang.org/docs/faq/) (fetched 2026-10-22). Saved by JangaFX (EmberGen) as a production user [not re-fetched]. FSM-in/out: none in the language; games written in it are hand-written loops. Round-trip loss to C: `context` must be threaded manually.
- **Rust (2010; 1.0 2015-05-15; editions 2015/2018/2021/2024).** Fix S, δ (total within safe Rust: no UB outside `unsafe`), **R as lifetime/ownership (author writes it; the compiler checks it)**, **T (`unsafe` blocks are the authority boundary)**; Free O (threads; `Send`/`Sync` fix which states may cross), B (macros by example + proc macros + `const fn`); Pt I (contracts only via external tools: Kani, Verus, Creusot). Memory: ownership + borrowing, no GC. Concurrency: threads + `async` (runtime-agnostic). **`async fn` lowers to "an enum with one variant per yield point... each variant stores the state needed to resume"; polling advances the state machine; the type is `!Unpin` because it may self-reference, so `Pin` is required** — [RFC 2394, 2018-03-30](https://rust-lang.github.io/rfcs/2394-async_await.html) (fetched). The RFC rejected "hot" (eager) async fns, green threads, stackful coroutines and effect systems as alternatives. Editions: "crates in one edition must seamlessly interoperate with crates compiled with other editions"; edition differences are "skin deep" because everything compiles to the same internal representation — [Rust Edition Guide](https://doc.rust-lang.org/edition-guide/editions/index.html) (fetched). Refused: a stable ABI (`repr(Rust)` layout unspecified — [Reference: type layout](https://doc.rust-lang.org/reference/type-layout.html) [not re-fetched]), GC, exceptions. Saved by Mozilla→Rust Foundation (2021), Linux kernel (6.1, 2022), Android metrics (LANGUAGE-REVIEW Part 1) and now a certified toolchain: Ferrocene is qualified ISO 26262 ASIL D, IEC 61508 SIL 3, IEC 62304 Class C, MIT/Apache open source — [ferrocene.dev](https://ferrocene.dev/en/) (fetched); Ferrous Systems donated the Ferrocene Language Specification to the Rust Project on 2025-03-26 to form the official Rust specification together with the Reference — [Rust Foundation](https://rustfoundation.org/media/ferrous-systems-donates-ferrocene-language-specification-to-rust-project/) (fetched). Formal: RustBelt (POPL 2018, Iris/Coq) — [RustBelt](https://plv.mpi-sws.org/rustbelt/popl18/) [not re-fetched]; MiniRust (operational semantics of MIR) — [minirust](https://github.com/minirust/minirust) [not re-fetched]. FSM-in: `async` (above); Embassy runs that lowering on microcontrollers in production — [embassy.dev](https://embassy.dev/) [not re-fetched]. FSM-out: `async`/`await` is the idiomatic refunctionalization. Round-trip loss: C→Rust via c2rust loses ownership (see C row); Rust→C has no mainstream path (mrustc is a bootstrap, not a product).
- **Swift (2014; ABI stable Swift 5 2019; Swift 6 2024-09; 6.2 2025-09-15).** Fix S (value types, copy-on-write, exclusivity law), δ, **O (actors SE-0306; Swift 6 strict concurrency checks data races at compile time; region-based isolation SE-0414)**, **T** (`unsafe` pointer types; `nonisolated`); Free R (ARC, deterministic but hidden; `~Copyable` since SE-0390 lets authors fix ownership); B (macros since 5.9, 2023; no CTFE). Pt I. Memory: ARC. Concurrency: async/await (SE-0296, 2021) + actors + structured tasks. **Swift 6.2 (2025-09-15) rolled the default back: "single-threaded by default" (code isolated to the main actor without annotation), `nonisolated async` functions now run in the caller's context, and parallelism is opt-in with `@concurrent`; the post credits user feedback that showed "where safety needed to feel more natural"** — [Swift 6.2 release post](https://www.swift.org/blog/swift-6.2-released/) (fetched). Refused: exceptions as unwinding (errors are typed returns), a GC. Saved by Apple platform mandate [opinion]. FSM-in: `async` functions are split by the compiler into continuation functions (LLVM coroutine splitting / CPS), with the suspended frame as state; the mechanism is documented in SE-0296 — [SE-0296](https://github.com/apple/swift-evolution/blob/main/proposals/0296-async-await.md) [not re-fetched]. Round-trip loss Swift→C: ARC retain/release are inserted by the compiler and have no C spelling; actor isolation is lost.
- **Nim (2008; 2.0 2023-08-01).** Fix S, δ, **B (AST macros: the strongest compile-time binding in the family; templates; `static`)**; Free R (ORC = cycle-collecting reference counting with move semantics, default since 2.0 — [Nim v2.0 released](https://nim-lang.org/blog/2023/08/01/nim-v20-released.html)), O (threads; `--threads:on` default in 2.0). Pt T, I. Memory: ORC/ARC. Concurrency: threads, channels, async via macros (`asyncdispatch` lowers `async proc` into closure iterators = state machines, implemented as a library macro, not a compiler pass) [not re-fetched]. Refused: none documented. Round-trip loss Nim→C (Nim compiles to C/C++/JS): exceptions become `setjmp` or goto-based error paths; AST macros are fully expanded (no loss); ORC becomes explicit counting code — [Nim memory management](https://nim-lang.org/docs/mm.html) [not re-fetched].
- **Hare (2022; 0.26.0 2026-02-13).** Fix S, δ, R (manual, "minimal runtime"); Free O (threads not in the language); Pt B (no macros, no generics), T, I. Latest release 0.26.0 announced 2026-02-13 by Drew DeVault; twelve maintainers, ~100 contributors; 1.0 not shipped — [harelang.org](https://harelang.org/) (fetched). Refused: generics, macros, a GC (the home page states manual memory management; the explicit no-generics rationale is in Hare blog posts I did not re-fetch). FSM-in/out: none. Round-trip to C: near-lossless (Hare targets qbe, close to C's model).
- **Jai (announced 2014; closed beta since 2019).** Fix S, δ, B (`#run` executes arbitrary code at compile time; the build is a Jai program); Free R (manual, context allocator like Odin), O; Pt T, I. Status: closed beta, no public release; evidence is the community wiki and Blow's videos — [Jai Community Library wiki](https://github.com/Jai-Community/Jai-Community-Library/wiki) [not re-fetched; weak evidence]. Refused: RAII, exceptions, GC, header files. No adoption data.
- **Carbon (2022; experimental, 0.1 MVP not dated).** Stated goals: C++ performance via LLVM, "software and language evolution" with tool-based upgrades, "practical safety," bidirectional C++ interop. Stated **non-goals: a stable ABI for the whole language and library, and perfect backward/forward compatibility**. Safety plan: automated C++→Carbon translation first, then incremental refactoring; replace UB with erroneous behavior where possible, mark the rest with visible `unsafe` syntax. Governance by numbered proposals; "not ready for use"; nightly toolchain only; a May 2026 talk references "graduating from the experiment" without defining it — [docs.carbon-lang.dev](https://docs.carbon-lang.dev/) (fetched). Coordinates: Fix S, δ, T (planned `unsafe`); Free R (manual/C++ model), O; Pt I. FSM-in/out: none yet.
- **Mojo (2023; 1.0 August 2026; compiler open-sourced 2026-08-18).** Compiler, tooling and language components published in the `modular` GitHub repo under Apache 2.0 with LLVM exceptions; Mojo reached 1.0 "last week" relative to the 2026-08-18 post; Modular is "A Qualcomm Company" (acquisition completed 2026-07-29 per the linked post) — [Modular blog](https://modular.com/blog/mojo-open-source) (fetched). Coordinates: Fix S, δ, R (ownership with ASAP destruction, `owned`/`read`/`mut` conventions — [Mojo manual: ownership](https://docs.modular.com/mojo/manual/values/ownership) [not re-fetched]), B (parametric metaprogramming evaluated at compile time via MLIR); Free O (GPU kernels: the target hardware fixes order); Pt I. Refused: the "Python superset" goal was dropped (RCE LANGUAGE-REVIEW §2.4 covers this with sources). FSM-in: none; Mojo's binding-time story is partial evaluation like Zig's, hosted in MLIR.
- **Hylo / Val (2022; renamed 2023).** Fix S as *values only* ("All in on Value Semantics"): no first-class references; mutation only through `inout` projections and subscripts; Fix R (single ownership, consume checks: the compiler rejects "deinitializing a value on some control-flow paths" and "using a consumed object"); Free O ("Structured concurrency made easy," "no function coloring," thread hopping); compiler written in Swift 6.3; "still in their early stages" — [hylo-lang.org](https://www.hylo-lang.org/) (fetched). Pt T (no unsafe shown), I. Formal lineage: "A Formal Definition of Swift's Value Semantics" (2020-11), "Implementation Strategies for Mutable Value Semantics" (2022) — same page. FSM-in: value semantics means δ consumes and returns S by construction (the closest in the family to RCE's own δ: S→S'). No adoption data.
- **Vale (2013 design; archived, last entry 2023-07-11).** Memory: generational references (every allocation carries a generation; references check it at use) + single ownership, "no borrow checker or garbage collector"; region borrow checking was "upcoming" when archived. Goal: "best language for high-performance low-overhead use cases, such as servers, games, simulations." Status: **archived, successor "Valen"** — [vale.dev](https://vale.dev/) (fetched). Coordinates: Fix S, δ, R (ownership) ; Pt O, T, I. FSM-in/out: none. Killed: single maintainer, no 1.0 [inference from the page].
- **Austral (2022).** Goals in the spec: simplicity ("fit in a single person's head"), correctness, security, readability over writability, maintainability (code "should keep compiling for decades," which "requires saying no to proposed language features"), modularity (interface/body files), strictness, restraint ("limits programmer power to minimize footguns, since human review is unreliable"). Linear types: Linear Universe Rule + Use-Once Rule; linear values represent capabilities (a linear `Terminal`); no GC ("would require an arbitrarily complex runtime"), no functors, no exceptions (contract violations crash), no SMT/theorem proving, no implicit destructors, no mixed expression/statement syntax — [Austral spec](https://austral-lang.org/spec/spec.html) (fetched). Coordinates: Fix S, δ, **R and T together (linearity = capability = authority: the only language here that fixes T through the type system)**; Pt O (no concurrency section), B (no macros), I beyond contracts. No adoption data.
- **Cyclone (2001–2006).** "A safe dialect of C": keeps pointers, structs, goto, manual memory and the preprocessor; adds pattern matching, ADTs, exceptions, **region-based memory management**, optional GC. Status: "no longer supported"; does not build on 64-bit; "the core research project finished, and the developers moved on"; "several of its ideas made their way into Rust" — [cyclone.thelanguage.org](https://cyclone.thelanguage.org/) (fetched). Papers: "Cyclone: A Safe Dialect of C" (USENIX 2002) — [paper](https://www.usenix.org/legacy/events/usenix02/full_papers/jim/jim.pdf) [not re-fetched]. Coordinates: Fix S, δ, R (regions with lifetime annotations, the direct ancestor of Rust lifetimes); Pt O, T (no unsafe keyword; whole program safe), I. Killed: research funding ended; 32-bit only. Round-trip loss Cyclone→C: region annotations erase (Cyclone compiled to C), so the C output is safe only by construction of the source.
- **Cforall / C∀ (2017 site; papers 2018–2021).** "Extending ISO C with modern safety and productivity features, while still ensuring backwards compatibility with C"; orthogonal, non-OO, "thinking inside the C box"; pre-release on GitHub; site © 2017 — [cforall.uwaterloo.ca](https://cforall.uwaterloo.ca/) (fetched; the page does not itself mention coroutines/monitors). The concurrency design (stackful coroutines, user-level threads, monitors) is in the Delisle/Buhr SP&E paper "Advanced control-flow and concurrency in C∀" (2021, DOI 10.1002/spe.2925) [not re-fetched; DOI from memory]. Coordinates: Fix S, δ, **O as stackful coroutines and monitors** (so *not* first-order state machines); Free R (manual); Pt T, I. Implementation: cfa-cc translates to C and calls gcc [not re-fetched]. Round-trip loss C∀→C: overloading is name-mangled, polymorphic functions are dictionary-passed (runtime cost, no monomorphization), coroutines need a stack-switching runtime. Adoption: academic only.
- **Fortran (1957; 77, 90, 2003, 2008, 2018, 2023).** Fix S (column-major arrays; the layout is the language), δ; **Fix O partially in the author's favor: dummy arguments may not alias (gives the optimizer freedom C lacks), `DO CONCURRENT` (2008) declares iteration-order independence, coarrays (2008) give PGAS parallelism**; Free R (allocatable arrays, automatic deallocation on scope exit, no GC); Pt T, I, B (no metaprogramming; generics are only now being standardized for 2028 via J3's templates work — [J3](https://j3-fortran.org/) [not re-fetched]). Memory: allocatables, no GC. Saved by HPC and LAPACK/BLAS; killed nowhere, just shrinking — [Wikipedia: Fortran](https://en.wikipedia.org/wiki/Fortran). FSM-in/out: none. Round-trip loss Fortran→C (f2c, 1990): `DO CONCURRENT` and the no-alias guarantee must become `restrict`; column-major becomes index arithmetic.
- **WebAssembly (MVP 2017; W3C Recommendation 2019; 2.0; 3.0 2025-09-17).** Target, not source. Fix S (linear memory is one byte array per module; the stack is not addressable), E (imports are the only events: the module is closed), δ (structured control flow only: `block`/`loop`/`br`, **no goto**; every instruction is deterministic except NaN payloads and the host), T (capability-style: a module can only call what it was given; WASI follows this), R (memory is sized in pages; fuel/gas metering is done by hosts, not the spec); Free O (threads are a proposal; the core spec is single-threaded; 3.0 added GC types, exceptions, tail calls, memory64) — [Wasm 3.0 announcement](https://webassembly.org/news/2025-09-17-wasm-3.0/) [not re-fetched]; formal semantics in the spec and in "Bringing the Web up to Speed with WebAssembly" (PLDI 2017), with a mechanized proof of type soundness — [PLDI 2017](https://dl.acm.org/doi/10.1145/3062341.3062363) [not re-fetched]. FSM-in: **Wasm is the family's canonical first-order machine: a module with exported functions and a linear memory is literally (S = memory + globals, E = imports/exports, δ = structured code)**; the Asyncify transform (Binaryen) turns blocking Wasm into a resumable state machine by instrumenting the call stack [not re-fetched]. Round-trip loss: C→Wasm→C via wasm2c re-emits linear memory as a byte array (types erased); irreducible control flow needs the "relooper"/"stackifier" and comes back as dispatch loops.

### Inferences
- The family has two concurrency ancestries and they lower differently: **stackful** (Modula-2 coroutines, Go goroutines, Cforall, D fibers) lowers to a runtime with stack switching and cannot be made a first-order machine without CPS; **stackless** (C++20 coroutines, Rust `async`, Swift `async`, Zig 0.10 async, Nim's macro-based async, Protothreads in C) *is* a defunctionalized state machine by construction. RCE's δ is on the stackless side by definition; Go-style `spawn` in SURFACE.md must therefore be lowered as a region with a mailbox, not as a stack.
- Ownership in the family is a lineage, not a set of independent inventions: Cyclone regions (2002) → Rust lifetimes (2010–2015) → SPARK ownership (2019), Mojo (2023), Hylo (2022), Austral linear types (2022), Vale generational references (2023, archived). Only Austral unifies R and T (linearity = capability).

### Gaps
- I did not find per-language, dated adoption numbers I would trust; TIOBE/Octoverse were not consulted because the assignment flags them as weak evidence, and the per-row "saved by" claims for Zig (Bun, TigerBeetle), Odin (JangaFX) and Jai are from memory, not re-fetched this session.
- No source found for a production *Oberon*, *Modula-3*, *D*, *Hare*, *Odin* or *Cforall* program compiled to an explicit state machine.
- The Hare rationale pages for "no generics / no macros" were not fetched; the home page confirms only manual memory and minimal runtime.

## Key question 1: accidental dimensions — what each language makes the author write that the behavior does not need

### Takeaway
The family's accidental dimensions cluster on **R** (lifetime/allocation written by hand in C, Zig, Odin, Rust) and **O** (isolation annotations in Swift 6, `Pin` in Rust), and each language's own rationale documents at least one of them as a cost it accepted knowingly.

### Cited Findings
- Rust's `Pin` exists because the compiler's own lowering may create self-referential frames; RFC 2394 makes the generated future `!Unpin`, uses `Pin::new_unchecked` in the expansion, and lists "making async functions implement `Unpin`" as an unresolved question — [RFC 2394](https://rust-lang.github.io/rfcs/2394-async_await.html). The author writes `Pin` for a property of the *lowering*, not of the behavior.
- Swift 6.2 made main-actor isolation the default and `nonisolated async` run in the caller's context, "reducing boilerplate," credited to user feedback — [Swift 6.2](https://www.swift.org/blog/swift-6.2-released/). The annotations Swift 6.0 required were, for most programs, accidental.
- Zig requires every allocating function to take an allocator parameter and to handle allocation failure — [Zig overview](https://ziglang.org/learn/overview/). This is a deliberate choice to make R a fixed coordinate even where behavior is allocation-indifferent.
- Odin passes an implicit `context` (allocator, logger, thread data) to every procedure so the author does not thread it — [Odin FAQ](https://odin-lang.org/docs/faq/). Same coordinate, opposite choice.
- Go removes R from the author's hand entirely (GC) and accepted the cost: the Discord GC-pause case is documented in RCE's own LANGUAGE-REVIEW.md Part 1 (with the Discord 2020 blog as source).
- Rust editions are deliberately "skin deep" because all editions share one internal representation — [Edition Guide](https://doc.rust-lang.org/edition-guide/editions/index.html). Surface syntax is an accidental dimension by the project's own statement.
- Austral's "Restraint" goal states the premise outright: "human review is unreliable," so the language limits power rather than asking the author to be careful — [Austral spec](https://austral-lang.org/spec/spec.html).
- C's "trust the programmer" principle (C99 Rationale) and the still-unsettled pointer-provenance model (TS 6010) mean the author writes addresses and lifetimes the behavior does not need and the standard cannot yet fully define — [C99 Rationale](https://www.open-std.org/jtc1/sc22/wg14/www/C99RationaleV5.10.pdf), [N3005](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3005.pdf) [both not re-fetched].

### Inferences
- In RCE's geometry, `Pin`, isolation annotations and allocator threading are **holonomy of the lowering**: they appear when a language exposes the coordinates of its own target machine to the author. RCE avoids them only if the Form IR, not the surface, owns regions and mailboxes (SURFACE.md §1 already assigns regions and mailboxes to the Form).
- Hylo's "no references" is the cleanest removal of an accidental dimension: with values only, aliasing cannot be written, so δ: S→S' is the only transition shape — which is RCE's own shape.

### Gaps
- I did not find a language-authored list titled "accidental" or "non-essential" for any language; the above is reconstructed from rationales. Ada's Rationale (Ichbiah 1979/1983) is the one explicit per-feature cost ledger and was not re-fetched.

## Key question 2: documented reasons for feature growth or restraint

### Takeaway
Restraint is documented as *process* in Go (proposal review group, architects, arbiter, Go 1 promise), as *philosophy* in Zig/Odin/Austral/Oberon, and as *mechanism* in Rust (editions); growth is documented as a *warning* in C++ (Vasa) and as a *rollback* in Swift 6.2.

### Cited Findings
- Process (Go): accept/decline/design-doc triage, weekly review group, architects (gri, iant, rsc), arbiter (austin), Go 2 process from 2018, Go 1 promise inviolable — [golang/proposal](https://github.com/golang/proposal).
- Philosophy (Zig, Odin, Austral, Wirth): quotations are in the rows above — [Zig overview](https://ziglang.org/learn/overview/), [Odin FAQ](https://odin-lang.org/docs/faq/), [Austral spec](https://austral-lang.org/spec/spec.html), [Wirth 1995](https://cr.yp.to/bib/1995/wirth.pdf) [not re-fetched].
- Mechanism (Rust): editions, "skin deep," `cargo fix`, no semantic changes — [Edition Guide](https://doc.rust-lang.org/edition-guide/editions/index.html).
- Rollback (Swift 6.2) and warning (C++ Vasa, P0977 2018): see rows — [Swift 6.2](https://www.swift.org/blog/swift-6.2-released/), [P0977R0](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2018/p0977r0.pdf) [not re-fetched].
- Successor diagnosis (Carbon): C++ cannot improve "because of decades of accumulated technical debt and a difficult evolution process"; evolution by numbered proposals — [docs.carbon-lang.dev](https://docs.carbon-lang.dev/).
- Corporate (Mojo): compiler open-sourced 2026-08-18; compiler contributions closed until year end; Modular is a Qualcomm company — [Modular](https://modular.com/blog/mojo-open-source).

### Inferences
- The languages with the fewest documented regrets (Zig, Odin, Austral, Oberon) are the ones with one designer and a written "no" list; the ones with the most documented growth pain (C++, Swift 6.0) are committee- or platform-driven. [opinion]
- RCE's own LANGUAGE-REVIEW.md "decision table" format is the Go/Austral pattern: a per-feature yes/no with a reason attached. It should also include a dated "declined" list, which Go keeps and no one else in this family publishes.

### Gaps
- WG21 attendance numbers (often quoted as 200+ per meeting) were not verified this session.

## Key question 3: formal semantics and verified subsets

### Takeaway
Only C (CompCert, Frama-C), Rust (RustBelt, MiniRust, Ferrocene/FLS), Ada/SPARK and WebAssembly have both a formal or qualified semantics and an industrial verification path; the rest of the family has neither.

### Cited Findings
- Ferrocene: TÜV SÜD-qualified Rust toolchain, ISO 26262 ASIL D, IEC 61508 SIL 3 (core library subset ASIL B / SIL 2), IEC 62304 Class C; fully open source including qualification documents — [ferrocene.dev](https://ferrocene.dev/en/).
- FLS: developed July 2022 inside Ferrocene; stewarded solely by Ferrous Systems since July 2023; donated 2025-03-26; to be merged with the Rust Reference into the official specification — [Rust Foundation](https://rustfoundation.org/media/ferrous-systems-donates-ferrocene-language-specification-to-rust-project/).
- RustBelt (POPL 2018) gives a Coq/Iris semantic soundness proof for a core of Rust including unsafe library code; cited by RCE SURFACE.md ref [2] — [RustBelt](https://plv.mpi-sws.org/rustbelt/popl18/) [not re-fetched]; MiniRust is the Rust project's executable operational semantics of MIR — [minirust](https://github.com/minirust/minirust) [not re-fetched].
- CompCert: verified C compiler (Coq) used in certified avionics — [compcert.org](https://compcert.org/) [not re-fetched]; Frama-C: ACSL-annotated C with WP/EVA plugins — [frama-c.com](https://frama-c.com/) [not re-fetched].
- SPARK: Ada subset with proof of absence of runtime errors and functional contracts — [AdaCore](https://www.adacore.com/about-spark), [SPARK LRM](https://docs.adacore.com/spark2014-docs/html/lrm/) [both not re-fetched].
- Cyclone: safety was argued in the USENIX 2002 paper and region papers, not mechanized; the project is unsupported — [cyclone.thelanguage.org](https://cyclone.thelanguage.org/).
- WebAssembly: the core spec is given as a formal small-step semantics with a mechanized soundness proof (PLDI 2017) — [PLDI 2017](https://dl.acm.org/doi/10.1145/3062341.3062363) [not re-fetched].
- Hylo: lineage includes "A Formal Definition of Swift's Value Semantics" (2020-11) — [hylo-lang.org](https://www.hylo-lang.org/).
- Austral explicitly refuses SMT/theorem proving as "too complex to implement" — [Austral spec](https://austral-lang.org/spec/spec.html).

### Inferences
- RCE's Lean 4 model (`spec/lean/`) places it with Wasm and MiniRust (operational semantics of the core), not with SPARK/Frama-C (program-level proof). The industrial lesson from Ferrocene is that a *spec* (FLS) plus a *qualified toolchain* was enough for ASIL D; a mechanized semantics was not required for qualification.

### Gaps
- No verified subset found for Go, Zig, Odin, Nim, D, Swift, Mojo, Carbon, Hare, Jai, Vale, Cforall or Fortran (Fortran has none I am aware of beyond compiler testing).

## Key question 4: compiled to state machines or event logs in production

### Takeaway
State-machine lowering is in production wherever stackless async is used (Rust/Embassy and Tokio, C++20 coroutines, Swift async, Protothreads in Contiki); event *logs* as the primary artefact are not a feature of any language in the family and live in application frameworks (event sourcing, game rollback).

### Cited Findings
- Rust `async` lowering is specified in RFC 2394 (2018) and is the basis of Embassy (embedded, no allocator) — [RFC 2394](https://rust-lang.github.io/rfcs/2394-async_await.html); [embassy.dev](https://embassy.dev/) [not re-fetched].
- C++20 coroutines lower to a frame + resume/destroy; used in production networking (ASIO, cppcoro, Folly) — [cppreference](https://en.cppreference.com/w/cpp/language/coroutines) [not re-fetched].
- Protothreads (Contiki OS, 2006) lower blocking C to a switch-based machine — [Dunkels 2006](https://dl.acm.org/doi/10.1145/1182807.1182811) [not re-fetched].
- Zig's 0.10 async did frame-based lowering; removed in 0.11 (2023); replacement is the `Io` interface — [0.11 notes](https://ziglang.org/download/0.11.0/release-notes.html) [not re-fetched].
- Go, Cforall, D fibers and Modula-2 use stack switching; no state-machine lowering exists for them (see rows).
- Event logs: Fowler's event sourcing pattern (2005) is framework-level — [Fowler](https://martinfowler.com/eaaDev/EventSourcing.html) [not re-fetched]; RCE's own README states "D is the one primary artefact" (RCEdb) and that replay runs "with every adapter disconnected."
- Ada Ravenscar fixes a static task set so that the whole tasking state is enumerable at compile time — [Wikipedia: Ravenscar profile](https://en.wikipedia.org/wiki/Ravenscar_profile) [not re-fetched].

### Inferences
- The cheapest FSM-in path in the family is uniformly "cut at the suspension points, store the live variables in an enum": Reynolds' defunctionalization applied to continuations — [Reynolds 1972](https://dl.acm.org/doi/10.1145/800194.805852); Danvy & Nielsen made the correspondence precise — [Defunctionalization at Work, 2001](https://dl.acm.org/doi/10.1145/773184.773202) [not re-fetched]. FSM-out is refunctionalization (Danvy & Millikin 2009), which is exactly `async`/`await` surface syntax.

### Gaps
- No public, dated case study found of a *game engine* compiling gameplay code to explicit state machines (rollback netcode logs inputs, which is an event log of E, but the user's memory file `boxing-rollback` may hold better evidence than the web did).

## Key question 5: dualities, shared blind spots, and what RCE should take, refuse, differentiate on

### Takeaway
The family's three dualities (async ≅ defunctionalized FSM; comptime ≅ partial evaluation; templates ≅ Turing-complete compile-time) are all *binding-time* phenomena; the shared blind spot is that none of the languages makes the log, totality of δ, or energy a coordinate at all.

### Cited Findings
- Rust async ≅ defunctionalized state machine: RFC 2394 "works like an enum with one variant per yield point" — [RFC 2394](https://rust-lang.github.io/rfcs/2394-async_await.html).
- Zig comptime ≅ partial evaluation: "evaluate functions and blocks of code at compile-time," lazy and order-independent — [Zig overview](https://ziglang.org/learn/overview/). Mojo and Jai do the same with MLIR / `#run` (rows above).
- C++ templates ≅ Turing-complete compile-time computation: Veldhuizen, "C++ Templates are Turing Complete" (2003) [not re-fetched]; D's CTFE and Nim's AST macros are the typed successors (rows).
- Hylo value semantics ≅ δ: S→S' with no aliasing (row above). Austral linearity ≅ capability/authority (row above). Wasm module ≅ closed Form (row above).
- Shared blind spots, with evidence: (a) **partial δ**: C/C++ UB, Rust panics, Go panics, Zig Illegal Behavior (the Zig page frames IB as "a razor sharp tool," i.e., accepted) — [Zig overview](https://ziglang.org/learn/overview/); (b) **O free by default**: every language except Ada Ravenscar and Swift 6.0 ships nondeterministic threads as the baseline, and Swift 6.2 moved back toward single-threaded default under user pressure — [Swift 6.2](https://www.swift.org/blog/swift-6.2-released/); (c) **R is never energy**: Zig and Odin fix *allocation*, Rust fixes *lifetime*, none fixes joules; (d) **I compactified**: only Ada 2012/SPARK, D contracts and Austral give intent a syntax; (e) **no log**: no language row has a first-class event log.

### Inferences (recommendations for RCE, flagged as opinion)
- **Take**: Rust's defunctionalized async as the *only* concurrency lowering (SURFACE.md already says each spawn is a region and each send an event; keep it stackless so D captures every resumption); Zig's allocator-as-parameter but hoisted into the Form (per-step arena, as SURFACE.md §3 does), so authors do not pay the accidental dimension; Ada Ravenscar's *static task set* as a rule for `spawn` (bounded set of regions known at admission); Austral's unification of R and T (a linear value is a capability — RCE's host contract with "one admitter" is already capability-shaped); Hylo's values-only S; Go's dated public "declined" list as a governance artefact; the FLS lesson that a prose spec plus qualified checker is enough for certification, so keep `spec/book/` normative and the Lean model supporting.
- **Refuse**: hidden control flow (Zig), GC (Zig/Odin/Austral/Rust/Hylo), exceptions (Odin/Austral/Rust/Zig: RCE already logs errors as outputs), stackful coroutines (Go/Cforall/Modula-2: they cannot be logged step-wise), `Pin`-style exposure of the lowering's own coordinates, editions-style syntax churn (RCE is tiny; it has no need), a stable ABI (Carbon/Rust both refuse it; RCE's ABI is the Form JSON and the log).
- **Differentiate on**: total δ (every input, every event, has a defined result — no language in the family claims this); D as primary artefact with replay under disconnected adapters; deterministic `select` by content-hash order (no family language fixes O deterministically without giving up concurrency); energy as an R coordinate (Zig/Odin make allocation visible; RCE can make *joules per step* visible via the host contract); `intent` + `example` as admission gates (SPARK proves contracts after the fact; RCE refuses the program at the gate).

### Gaps
- I found no source that measures the *round-trip loss* (holonomy) of a language pair quantitatively; all transpiler losses above are structural (which constructs have no image), not measured. A measurement would need a corpus translated C→Rust→C (c2rust + a Rust-to-C backend) and a diff of behaviors; none was found.
- Energy per language is covered in RCE's LANGUAGE-REVIEW Part 1 (Pereira et al.) and was not re-researched here.
