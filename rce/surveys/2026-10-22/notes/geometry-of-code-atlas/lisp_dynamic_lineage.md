# Lisp / Smalltalk / Dynamic-Language Lineage — one chart in the atlas

Frame used throughout: a language is a chart on behavior space that FIXES, FREES or COMPACTIFIES each of eight coordinates: (1) state layout, (2) event alphabet, (3) transition/step, (4) order/concurrency, (5) resource/energy, (6) trust/authority, (7) binding time, (8) intent/spec. A Form P=(S,E,δ,D,λ) fixes all eight. The defining move of this whole lineage is **compactifying the type coordinate (part of state layout) to a point, and freeing binding time all the way to run time**. Everything else in the lineage follows from those two choices.

Provenance tags: [F] = fetched and verified this session; [K] = established fact from primary sources I did not re-fetch this session (URL given; writer should treat as high-confidence but unverified here); [O] = opinion/inference.

## Key Question 0: The per-language rows (same schema for each)

### Takeaway
Every language in this lineage frees binding time and compactifies types; they differ mainly on (a) which *state model* they fix (cons cells / objects / images / immutable values), (b) whether the program text is itself a canonical tree (Lisps yes, everyone else no), and (c) whether a cheap mechanical translation to an explicit state machine exists (it exists wherever the language already has first-class continuations, generators or an IOC macro; it does not exist for eval-, reflection- or image-dependent code).

Schema per row: **year | fixed / freed / compactified coordinates | object-value model | metaprogramming & binding time | refused | killed/saved (evidence) | translation INTO a first-order state machine ↔ OUT, and documented round-trip loss.**

### Cited Findings (rows)

- **Lisp 1.5 (1960/1962)** | fixes: transition = eval/apply over S-expressions (the metacircular evaluator is the spec); frees: binding time (eval at run time), state layout (cons cells + property lists); compactifies: types (atoms vs conses only), trust, resource, intent. | Model: everything is a cons or atom; code is data. | `eval`/`quote`, FEXPRs, dynamic scope (the "funarg problem"). | Refused: static types, fixed syntax, compile-time binding. | Saved by: garbage collection + REPL + the AI-lab culture; what "killed" the original was dynamic scoping and FEXPR unsoundness, fixed in Scheme/Common Lisp. — McCarthy, "History of Lisp" HOPL I 1978 [K] https://doi.org/10.1145/800025.808387 ; Lisp 1.5 Programmer's Manual (MIT Press 1962) [K]. | Translation IN: the metacircular evaluator is itself a one-step relation (state = environment+control, event = next form); Queinnec, *Lisp in Small Pieces* (CUP 1996) [K] shows CPS + defunctionalization produce an explicit register machine. Loss: `eval` of runtime-constructed code has no finite event alphabet, so the translation is only total for the eval-free fragment [O].

- **Common Lisp (CLtL 1984; ANSI X3.226-1994)** | fixes: step semantics across ~1,000 standard operators, condition system (restarts), CLOS metaobject protocol as a documented reflective transition. Frees: binding time (compile-time via macros + `eval-when`, load-time, run-time `eval`), everything else. Compactifies: types to *optional declarations* (type decls are promises to the compiler, not checks — the chart lets you re-expand the type coordinate locally). | Model: generic functions + multiple dispatch (CLOS), mutable structures, packages, images (SBCL `save-lisp-and-die`). | Macros (unhygienic), reader macros, MOP, `eval`, image dumping. | Refused: one object model (it has structs, classes, conditions), single implementation. | Killed (as mainstream): the 1987–1993 "AI winter" and Lisp-machine collapse; saved: SBCL/CCL, ANSI stability (spec unchanged since 1994). — Steele & Gabriel, "The Evolution of Lisp," HOPL II 1993 [K] https://doi.org/10.1145/155360.155373 | IN: same CPS/defunctionalization path; `handler-bind`/restarts map to event+λ outputs. Loss: MOP-dependent code (runtime class redefinition, `update-instance-for-redefined-class`) has no fixed S.

- **Scheme (1975; R5RS 1998; R7RS-small 2013)** | fixes: step = applicative-order λ-calculus with first-class continuations, tail calls (proper), lexical scope; frees binding time but *introduces phases* (R6RS/R7RS libraries, `syntax-rules` hygiene). Compactifies: types, resource, trust. | Model: pairs, closures, continuations as values. | Hygienic macros (`syntax-rules`), `call/cc`, `dynamic-wind`, `eval` with explicit environment specifier (R5RS). | Refused: a large standard library (R5RS ~50 pages), a module system (until R6RS 2007, which split the community; R7RS-small 2013 retreated). | Neither killed nor saved: perpetual teaching language; R7RS-large still unfinished as of 2024–25 [K] https://r7rs.org . | IN: `call/cc` ↔ state machine is *the* canonical result — a CPS-converted program is a first-order machine whose continuation is the explicit state; Racket's stateless web server uses exactly this (see Racket row) [F]. OUT: any state machine is trivially a tail-recursive Scheme loop. Loss: `dynamic-wind` and non-serializable native continuations (see Racket restrictions) [F].

- **Racket (PLT Scheme 1995; renamed 2010)** | fixes: *phases* — macro expansion is a separate phase with its own environment (`for-syntax`), modules are first-class compile-time units, `#lang` lets each module fix its own chart. Frees: binding time per phase. Compactifies: types (base), but Typed Racket (2008) re-expands them with three semantics (see Q3). | Model: immutable pairs by default (a deliberate break with Scheme), structs, contracts at module boundaries. | Hygienic macros with full phase separation, `syntax-parse`, language-oriented programming. | Refused: unhygienic macros as default, single language. | Saved by: academic funding and the "language workbench" niche; never mass-adopted (in MultiPL-E/The Stack, Racket ≈0.5 GB vs 64 GB Python [F]). — Flatt, "Creating Languages in Racket" CACM 2012 [K]. | IN: `#lang web-server` stateless servlets: after macro expansion the code is rewritten by `letrec`→`let` + imperative, A-normalization, continuation marks recorded per expression, `call/cc` replaced by gathering marks, then **defunctionalized** so every `lambda` becomes a serializable struct; continuations can be stored on the client or on disk and survive server restart. Documented losses: continuations crossing untransformed modules (e.g. built-in `map` with a capturing lambda) fail with "unsafe context"; `parameterize` is disallowed (parameterizations unserializable); changing a constant invalidates all saved continuations; the server-side store is not serialized. — [F] https://docs.racket-lang.org/web-server/stateless.html ; McCarthy, "Automatically RESTful Web Applications," ICFP 2009; Pettyjohn et al., "Continuations from Generalized Stack Inspection," ICFP 2005 [cited there, F].

- **Clojure (2007)** | fixes: *state layout* = persistent immutable data (HAMT maps, vectors) with identity/state separated via refs/atoms/agents (epochal time model); fixes order via STM/atoms rather than locks; frees binding time (JVM, `eval`, macros, REPL); compactifies types (with `clojure.spec` 2017 as a runtime, data-driven re-expansion of the intent coordinate). | Model: values are immutable; "everything is a sequence"; host interop. | Unhygienic-but-namespaced macros (auto-gensym `#`, symbol namespace qualification), reader with EDN as a data format, `eval`. | Refused: classes as the organizing unit, hidden mutation, a type system (Hickey's stated position). | Saved by: JVM hosting and the data-orientation niche; not mass-adopted. — Hickey, "A History of Clojure," HOPL IV 2020 [K] https://doi.org/10.1145/3386321 . | IN: `core.async` `go` macro (2013) is an IOC (inversion-of-control) analyzer that rewrites only the channel *parking* ops (`>!`, `<!`) into a state machine; blocking ops and arbitrary I/O are not allowed inside `go` blocks; as of core.async 1.9.847-alpha3 (11 Mar 2026) go blocks are unchanged and still use the go analyzer, while the `io-thread` executor moved to virtual threads on Java 21+. — [F] https://clojure.org/news/2026/03/11/async_virtual_threads . Loss: the transform does not cross function boundaries (parking inside a called fn is an error) and loses the stack as a debugging artefact [K, widely documented in the core.async issue tracker].

- **Smalltalk-80 (1972/1980)** | fixes: *state layout = the image* (one heap of objects, including classes, compiler and IDE), transition = message send with late binding of every send, uniform object model. Frees: binding time entirely (methods are compiled into the live image; `doesNotUnderstand:`); frees authority (any object can inspect/modify any other). Compactifies: types, resource, intent, trust. | Model: everything is an object; classes are objects; metaclasses. | Reflection (`thisContext`, `become:`), live image, the `.changes` file. | Refused: files as the unit of program, static compilation, a separate compile step, textual program as the primary artefact. | Killed by: the image as a non-composable, non-diffable, non-mergeable unit (see Q2); Java (1995) taking the VM+GC+OO ideas without the image; commercial fragmentation (ParcPlace/Digitalk). Saved partially by Squeak (1996) and Pharo (2008). — Kay, "The Early History of Smalltalk," HOPL II 1993 [K] https://doi.org/10.1145/155360.155364 . | IN: the `.changes` file is already an append-only log of source-level events (see Q2) but **of source edits, not of program behavior**; `thisContext` gives a first-class reified stack, so a Smalltalk process is already a state-machine with inspectable frames. Loss: image state outside the changes log is unrecoverable from the log alone ("the log holds information not in the image" and vice versa after a crash) [F].

- **Self (1987, Sun/Stanford)** | fixes: state = objects with slots, no classes (prototypes + `clone`), transition = message send with every slot access a send. Frees: binding time to the extreme (maps/hidden classes and adaptive inlining invented here to recover it at run time). Compactifies: types, class/instance distinction (to a point). | Model: prototypes, `parent*` slots, images. | Reflection via mirrors (the origin of the mirror concept); dynamic deoptimization. | Refused: classes, static layout. | Killed by: Sun's commitment to Java (1995); saved as a technology transplant: Self's maps → V8 hidden classes, HotSpot's deoptimization, JavaScript's prototype model. — Ungar & Smith, "Self: The Power of Simplicity," OOPSLA 1987 [K] https://doi.org/10.1145/38765.38828 ; Hölzle, Chambers, Ungar, "Debugging Optimized Code with Dynamic Deoptimization," PLDI 1992 [K]. | IN/OUT: deoptimization *is* a documented translation out of a compiled form back to the interpreter's first-order state (frame reconstruction); it is the earliest engineered "round trip" in the lineage, and its documented cost is the need to keep enough metadata to rebuild frames [K].

- **Io (2002, Dekorte)** | fixes: everything is a message send on prototypes; frees: binding time (messages are first-class, lazily evaluated args give macros-for-free), concurrency via coroutines/actors/futures; compactifies types. | Model: prototypes with `clone`, messages as objects. | Refused: syntax (nearly none), compile step. | Status: hobby/influence language; no adoption evidence beyond its own site [K] https://iolanguage.org . | IN: coroutine-based, so the same generator↔state machine route applies; no documented tooling.

- **Python (1991; 2.0 2000; 3.0 Dec 2008)** | fixes: step = CPython bytecode with the GIL fixing *order* (single interpreter thread holds the lock; PEP 703 free-threaded build experimental in 3.13 (Oct 2024) and 3.14 (Oct 2025)) [K] https://peps.python.org/pep-0703/ ; frees binding time (`exec`, `eval`, `__getattr__`, metaclasses, `import` hooks); compactifies types (PEP 484 type hints, 2014, are *ignored at run time* — the chart explicitly refuses to re-expand the coordinate; mypy is external). | Model: everything is an object, mutable by default, dicts for namespaces, reference-counting + cycle GC. | Decorators, metaclasses, `ast` module, monkey-patching; no macros (PEP 638 syntactic macros, 2020, deferred). | Refused: macros, tail-call elimination (van Rossum 2009), multi-line lambdas, a JIT (until 3.13's experimental copy-and-patch JIT, 2024). | **Python 3 transition**: 3.0 released 3 Dec 2008; Python 2.7 EOL set by PEP 373 at 1 Jan 2020 — an 11-year migration; the lesson generally drawn is that breaking the text-level chart of a dynamic language is expensive because there is no type coordinate to drive mechanical migration (`2to3` was syntactic only) [K] https://peps.python.org/pep-0373/ . Saved by: scientific stack (NumPy 2006, pandas 2008), then ML (PyTorch 2016), then LLMs (see Q5). | IN: **generators (PEP 255, 2001) are the state-machine translation**: a generator is a heap-allocated frame whose instruction pointer is the state; `async def`/`await` (PEP 492, 2015) reuse the same mechanism [K] https://peps.python.org/pep-0255/ . OUT (documented loss): Cython compiles Python to C but keeps the CPython object model (dynamic attributes remain dynamic; speedup only with `cdef` annotations); Nuitka's own compatibility notes target "100% CPython compatibility" precisely because semantics live in the runtime, not the text; GraalPy (Oracle) reports compatibility against the top PyPI packages rather than claiming full semantics [K] https://www.graalvm.org/python/ . Round-trip loss: any program that depends on `frame.f_locals`, `sys.settrace`, or C-extension ABI fails to translate; this is the standard reason "Python compilers" ship a compatibility matrix rather than a proof [O].

- **Ruby (1995; 1.9 2007; 3.0 Dec 2020)** | fixes: everything-is-an-object including `nil` and integers, message send with `method_missing`; frees binding time maximally (open classes, `define_method`, `instance_eval`, refinements); compactifies types (RBS + Steep/Sorbet re-expand externally; Sorbet (Stripe, open-sourced 2019) is a gradual *nominal* checker with `T.untyped` as the dynamic type, and its runtime `sig` checks are opt-in) [K] https://sorbet.org . | Model: classes + mixins (modules), blocks/procs/lambdas as three closure kinds, `Fiber` (1.9) for coroutines. | Refused: static types in the core (Matz, repeatedly, "I don't want to write types"), multiple inheritance. | **Rails dependence**: Ruby's adoption curve is Rails' (2004–2008 rise, post-2015 relative decline on surveys); treat survey rankings (Stack Overflow, Octoverse) as weak evidence [O; survey data not fetched this session]. | IN: `Fiber` and `Enumerator::Lazy` give the same frame-as-state route; OUT: TruffleRuby (GraalVM) documents incomplete C-extension compatibility; JRuby documents `ObjectSpace` as disabled by default — i.e. reflection on the whole heap is the un-translatable feature [K].

- **JavaScript (May 1995, "ten-day hack" at Netscape; ES3 1999; ES5 2009; ES2015)** | fixes: *event alphabet and order* — the browser event loop (single-threaded run-to-completion, then microtask/macrotask queues) is the only widely deployed language whose *order* coordinate is fixed by the host, not the language; transition = prototype-chain lookup (from Self); frees binding time (`eval`, `with`, dynamic `this`, property addition); compactifies types. | Model: prototypes, objects as dictionaries, hidden classes in V8 (from Self) [K]. | `eval`, `Function`, `Proxy`/`Reflect` (ES2015), no macros (sweet.js was an experiment). | Refused: ES4's classes + optional static types + packages (abandoned 2008 in the "Harmony" compromise), and any backward-incompatible change ("don't break the web") [K; paper verified to exist and to cover 1995–2015, specific claims not verified this session] — Wirfs-Brock & Eich, "JavaScript: The First 20 Years," HOPL IV 2020 [F for existence/abstract] https://zenodo.org/record/4960086 . | **Platform monopoly** is the adoption mechanism: the only language the browser runs natively; TypeScript (2012) then re-expanded types *without* runtime enforcement (erasure) so the dynamic chart stays the deployment chart. | IN: **generators (ES2015) ↔ state machines is a documented compiler pass**: Regenerator (Facebook, 2013–) and TypeScript's downlevel `__generator` helper compile `function*`/`async` to an explicit `switch`-on-state machine for ES5 targets [K] https://github.com/facebook/regenerator . Loss: `arguments`, `this` capture and stack traces differ; TypeScript erasure means type-level intent is lost at the JS boundary (no runtime check) — the asymmetric holonomy of TS→JS→TS is that *all* type information is lost on the forward map [O, grounded in TS's documented erasure design].

- **TypeScript (Oct 2012; 1.0 Apr 2014)** | re-expands the type coordinate *structurally* and *unsoundly by design* (bivariant method params, `any`, no runtime checks); binding time: types bind at compile time and vanish. | Refused: soundness (explicitly a non-goal in the TS design goals wiki) [K] https://github.com/microsoft/TypeScript/wiki/TypeScript-Design-Goals . | Evidence on cost of the re-expansion: MultiPL-E (Codex, 2022) found removing precise types from TypeScript prompts hurt pass@1 by 2.5 points (p<0.001), but found **no overall effect of type annotations** on pass@1 across languages (p=0.33) [F] https://arxiv.org/pdf/2208.08227 .

- **Lua (1993; 5.0 2003; 5.4 2020)** | fixes: one data structure (the table) for state layout; transition = register VM; coroutines (5.0) fix a *cooperative* order coordinate; frees binding time (metatables, `load`); compactifies types. | Model: tables + metatables, prototypes-by-convention, first-class functions, no classes. | `load`, metatables, `debug` library (full frame access), `__index`. | Refused: a standard class system, a standard library of size, Unicode strings, a module ecosystem of size. | Saved by: embeddability (game industry, nginx/OpenResty, Redis, Roblox-Luau); tiny spec. — Ierusalimschy, de Figueiredo, Celes, "A Look at the Design of Lua," CACM 2018 / HOPL IV 2020 [K] https://doi.org/10.1145/3386329 . | IN: Lua coroutines are *asymmetric, stackful* — the state is a whole C-stack-free Lua stack, so the "generator → switch state machine" translation is unnecessary at the VM level; the documented loss is that a coroutine cannot yield across a C-call boundary (pre-5.2 "attempt to yield across metamethod/C-call boundary"; `lua_yieldk` continuations added in 5.2) [K] https://www.lua.org/manual/5.4/ . MultiPL-E: Lua ranked the "9th-best language" for Codex despite low data volume [F].

- **Perl (1987; 5.0 1994; Perl 6/Raku split 2000–2015)** | frees binding time (`eval STRING`, `AUTOLOAD`, typeglobs, source filters); compactifies types to *context* (scalar/list/void — a type coordinate that is replaced by a *contextual evaluation* coordinate no other language has). | Model: scalars/arrays/hashes + blessed references as objects; `tie`. | Refused: a single object system (Moose/Moo are CPAN), a syntax that can be parsed statically (Perl parsing is undecidable: Kegler, "Perl is undecidable," 2008, because `BEGIN` blocks can alter the parse [K] http://www.jeffreykegler.com/Home/perl-and-undecidability ). | Killed by: the 15-year Perl 6 gap and Python/Ruby absorbing its niches; survey data weak [O]. | IN: no cheap route — the undecidable parse means there is no canonical tree, so no canonical state machine without executing `BEGIN` blocks first [O, grounded in Kegler].

- **PHP (1995; PHP 5 2004; PHP 7 Dec 2015; PHP 8 Nov 2020)** | fixes: *request lifecycle as the event alphabet* — each HTTP request is a fresh process state (shared-nothing), which is incidentally the closest any mainstream language comes to "state = result of applying one event to an initial state"; frees binding time (`eval`, variable variables, autoloading); compactifies types, then re-expands gradually (scalar type declarations PHP 7.0, `declare(strict_types=1)` per file, union types 8.0, enums 8.1) with *runtime-enforced* coercion/TypeError — the opposite of TypeScript's erasure [K] https://www.php.net/manual/en/language.types.declarations.php . | Refused: a coherent standard library naming scheme, a non-web runtime for 20 years. | Saved by: WordPress/Facebook (HHVM, Hack 2014 as the gradual-typed fork). | IN: the per-request shared-nothing model makes each script a single δ application; documented loss on translation OUT: HHVM dropped PHP support in 2019 (3.30 last) because Hack's typed chart diverged from PHP's [K] https://hhvm.com/blog/2018/09/12/end-of-php-support-future-of-hack.html .

- **Julia (2012; 1.0 Aug 2018)** | fixes: *transition by multiple dispatch on dynamic types with type-specialized JIT* — the "two-language solution" is to make binding time *late but specialized*: types are inferred at the first call and native code is cached per method signature; compactifies types in the *surface* (no annotations required) but NOT in the runtime (every value carries a concrete type and the compiler sees it). | Model: values with concrete types, immutable structs by default, `Expr` as data (Lisp-like homoiconicity: Julia macros operate on `Expr` trees; `@generated` functions bind at type-inference time). | Refused: classes/inheritance of concrete types, a GIL-like order coordinate, interpreted-by-default. | Saved by: scientific computing niche; documented cost is time-to-first-plot/compile latency, attacked by precompilation caches in 1.9 (May 2023) and 1.10 (Dec 2023) [K] https://julialang.org/blog/2023/04/julia-1.9-highlights/ . — Bezanson, Edelman, Karpinski, Shah, "Julia: A Fresh Approach to Numerical Computing," SIAM Review 59(1), 2017 [K] https://doi.org/10.1137/141000671 . | MultiPL-T evidence: Julia pass@1 StarCoderBase-15B 21.1 → 35.2 after 45,000 translated training functions [F] https://arxiv.org/pdf/2308.09895 . | IN: Tasks (`Channel`, `@async`) are stackful coroutines; no documented state-machine compiler pass. Loss: `@generated` and `eval` at world-age boundaries ("world age" errors) are the documented failure of late binding in a specializing compiler [K].

- **R (1993; S 1976)** | fixes: *lazy argument evaluation with promises* (binding time of arguments is at first use), copy-on-modify vectors, environments as first-class state; frees binding time (`eval(parse(text=))`, `substitute`, non-standard evaluation); compactifies types (vectors with modes; four object systems S3/S4/RC/R6 that disagree). | Model: everything is a vector; functions carry environments. | Refused: one object system, a module system (packages + namespaces only), performance. | Saved by: CRAN + statistics; never left the niche; MultiPL-E Codex coefficient −3.69 log-odds vs Python, one of the worst [F]. — Ihaka & Gentleman, "R: A Language for Data Analysis and Graphics," JCGS 1996 [K]. | IN: no cheap route; non-standard evaluation (`substitute`) means a function's event alphabet includes the *unevaluated caller expression*, which defeats first-order translation [O].

- **Tcl (1988)** | fixes: *everything is a string* — the state layout is a single string type (with dual-ported internal representations since 8.0, 1997); transition = command dispatch; frees binding time to the maximum (`uplevel`, `upvar`, `eval` of strings, `proc` redefinition); compactifies types to one point. | Model: strings, lists-as-strings, dicts; `[incr Tcl]`/TclOO objects added later. | Refused: a type system of any kind, syntax beyond quoting. | Saved by: Tk, embedding (EDA tools), Expect; marginal now [O]. — Ousterhout, "Tcl: An Embeddable Command Language," USENIX 1990 [K]. | IN: string-only state makes serialization trivial (every state is already text) — Tcl is the only language in the row where S is canonical by construction; loss: `uplevel` means the transition depends on the caller's frame, so δ is not a function of (S,E) alone [O].

- **Erlang (1986; open-sourced 1998) / Elixir (2011; 1.0 2014)** — dynamic-typing aspect only. | compactifies types at the language level; re-expansion came in two waves: Dialyzer (success typing, 2005; Lindahl & Sagonas, "Practical Type Inference Based on Success Typings," PPDP 2006 [K]) which never reports false positives and therefore proves nothing about absence of errors; then Elixir's **set-theoretic gradual types** (Castagna, Duboc, Valim, "The Design Principles of the Elixir Type System," 2023): `dynamic()` is a gradual type; existing code is checked as `(dynamic() -> dynamic())`; 1.18 shipped full type inference of patterns; 1.19 covers all constructs except guards; 1.20 expected to complete inference; typed structs and function signatures are later milestones; where `dynamic()` is present, "the type of a variable or expression is checked at runtime"; without it the system behaves as a static one [F] https://elixir.hexdocs.pm/1.19/gradual-set-theoretic-types.html . | Model: immutable terms, process-local heaps (state layout fixed per process), `:erlang.binary_to_term` makes every S serializable. | Refused: shared mutable state, static types (for 30 years). | IN: `gen_statem`/`gen_fsm` are *literal* first-order state machines in the standard library — the lineage's only language where the state-machine form is the idiom rather than a translation target [K] https://www.erlang.org/doc/man/gen_statem .

- **Dylan (1992, Apple; 1995 infix syntax)** | fixes: CLOS-like generic functions + classes with *sealing* (a declared commitment that lets the compiler bind early) — the first language to make binding time a per-declaration dial (`sealed`/`open`); compactifies types optionally. | Refused: S-expression syntax (switched to infix 1995), which lost the Lisp community without winning the C one. | Killed by: Apple cancelling the Newton/Dylan project in 1995; Open Dylan survives as a niche [K] https://opendylan.org . — Shalit, *The Dylan Reference Manual* (1996) [K]. | Relevant to the atlas as the explicit experiment in *partial de-compactification by declaration* [O].

- **Gradual-typed descendants summary** (TypeScript 2012 erasure/unsound; Sorbet 2019 nominal, opt-in runtime sigs; mypy 2012/PEP 484 2014 erasure, external; Typed Racket 2008 sound/deep, with shallow and optional semantics added in Racket 8.7, Nov 2022 [F] https://blog.racket-lang.org/2022/11/shallow-typed-racket.html ; Elixir 2023–2026 sound set-theoretic with `dynamic()`; Hack 2014 runtime-enforced; PHP 7+ runtime-enforced). Pattern: the industry-adopted re-expansions (TS, mypy) are *erasure* — they put the coordinate back for the author and the LLM but not for the runtime — while the sound ones (Typed Racket deep) pay the contract tax measured in Q3 [O].

### Inferences
- The lineage's shared invariant, in Form terms: δ is total only *dynamically* (there is always a `doesNotUnderstand:`/`TypeError` branch), so the "refused" branch of a Form is *implicit and uniform* rather than named per case; this is exactly the thing RCE's `error` declarations make explicit [O].
- The translation INTO a state machine is cheap exactly where the language already reifies control (continuations, generators, fibers, `thisContext`, coroutines) and expensive where it reifies *environment* (`eval`, `uplevel`, `substitute`, MOP, `ObjectSpace`). Reified control is a state coordinate; reified environment makes the event alphabet unbounded [O].
- The only two languages whose S is canonical by construction are Tcl (everything is a string) and Erlang (every term is `term_to_binary`-serializable); the Lisps have canonical *programs*, not canonical *states* [O].

## Key Question 1: What does compactifying the type coordinate buy and cost? (measured evidence)

### Takeaway
Measured LLM evidence does not show that type annotations per se help or hurt (MultiPL-E 2022: no overall effect, p=0.33); what dominates is **training-data volume**, which is a consequence of adoption, which in this lineage was bought by compactifying types. Precise TypeScript types help slightly (−2.5 pts when removed). Human bug-rate evidence is contested.

### Cited Findings
- MultiPL-E (Cassano et al., arXiv 2208.08227 v4, 19 Dec 2022; later IEEE TSE 2023): Codex HumanEval Python pass@1 45.9% (temp 0.2); mixed-effects log-odds vs Python: JavaScript −0.27, TypeScript −0.27, PHP −0.30, Ruby −0.68, Lua −1.04, Julia −1.91, Perl −2.00, R −3.69, Racket −3.78. "Code generation performance is correlated with language popularity." "We observe no overall effect of type annotations on Codex pass@1 rates" (p=0.33). Removing precise types from TypeScript hurt by 2.5 points (p<0.001). Codex JS was +2.3 pts vs Python, not significant (p=0.43). — [F] https://arxiv.org/pdf/2208.08227
- MultiPL-T (Cassano et al., OOPSLA2 2024, PACMPL 8(OOPSLA2) art. 295): pass@1 base→fine-tuned, StarCoderBase-15B: Racket 11.8→21.0, OCaml 6.9→19.9, R 10.2→17.3, Julia 21.1→35.2, Lua 26.6→31.0; Python 30.6 for the same model. The Stack holds ~64 GB Python vs ~1 GB OCaml and ~0.5 GB Scheme/Racket; the Racket subset was mostly documentation so Scheme was used. - Token cost by language: Wu, Anderson, Guha, "The Best Programming Language for Tokenmaxxing" (arXiv 2607.22807, submitted 24 Jul 2026): five models on Python, Java, Rust, OCaml; token cost "varies dramatically by programming language" after controlling for difficulty, consistently across models; agents produce non-compiling solutions in unfamiliar languages, revise already-passing solutions, and "prototype in Python to avoid unfamiliar target languages." Per-language numbers were not retrievable (PDF had no machine-readable text via the fetch tool). — [F abstract only] https://arxiv.org/abs/2607.22807

### Inferences
- "Buy": zero annotation burden → faster authoring and more corpus → better LLM priors. The causal chain adoption→corpus→pass@1 is supported by MultiPL-E/T; the direct effect of annotations is null-to-slightly-positive [O from F].
- "Cost": the error branch of δ is discovered at run time; there is no mechanical migration when the text-level chart changes (Python 2→3 took 11 years, PEP 373) [O from K].
- For a model-authored Form surface, the implication is that the *surface* should look like the high-corpus charts (Python/JS syntax habits) while the *Form* keeps the coordinates fixed — which is what SURFACE.md already proposes ("Python readability … none; pure notation") [O].

## Key Question 2: Homoiconicity — why "code is data" did not yield canonical forms of behavior

### Takeaway
Lisps have a canonical *syntax* tree (the reader fixes it) but not a canonical *semantics*: macros (binding time), phases (Racket), reader extensibility (Clojure reader/EDN, CL reader macros) and `eval` mean the tree's meaning is a function of an environment that is itself mutable program state. Canonical text ≠ canonical behavior because the expansion environment is not part of the tree.

### Cited Findings
- Racket's stateless web-server shows what it takes to get a *canonical behavioral form* out of a Lisp: a six-step post-expansion rewrite (letrec elimination, ANF, continuation marks, call/cc replacement, external-call marking, defunctionalization), and even then continuations through untransformed modules fail ("unsafe context"), `parameterize` is disallowed, and changing a constant invalidates every saved continuation — i.e., the canonical form is *hash-of-text-sensitive* rather than behavior-sensitive. — [F] https://docs.racket-lang.org/web-server/stateless.html
- Clojure's `go` macro rewrites only the parking ops; blocking ops and I/O are excluded by rule, not detected; the transform has stayed structurally unchanged through 2026 (1.9.847-alpha3) while the runtime around it moved to virtual threads. — [F] https://clojure.org/news/2026/03/11/async_virtual_threads
- Scheme hygiene (`syntax-rules`, R5RS 1998) and Racket's phase separation exist precisely because unhygienic expansion makes the tree's meaning depend on the expansion-time environment. — R7RS-small [K] https://small.r7rs.org/ ; Flatt, "Composable and Compilable Macros: You Want it When?" ICFP 2002 [K] https://doi.org/10.1145/581478.581486 .
- Perl is the extreme counter-case: parsing is undecidable because `BEGIN` blocks run during parsing (Kegler 2008) — there is not even a canonical tree. [K] http://www.jeffreykegler.com/Home/perl-and-undecidability

### Inferences
- In atlas terms: homoiconicity fixes the *text→tree* transition map to the identity; it leaves the *tree→behavior* map parameterized by (expansion env, phase, reader table). RCE's choice to make the Form itself the artefact (not the text) is the move the Lisps never made: they canonicalized the input of δ, not δ [O].
- The documented losses in Racket's serializable continuations (constant changes invalidate continuations) are a direct observation of holonomy: the round trip text→continuation→text is not stable under semantically neutral edits [O].

### Gaps
- No source fetched quantifying how often macro hygiene bugs occur in practice; the claim that hygiene matters is from the language designers' rationale, not measurement.

## Key Question 3: Image-based systems as ancestor of "the log is the program"

### Takeaway
Smalltalk's `.changes` file got the mechanism right — an append-only log written immediately after each operation, replayable after a crash — but logged *source edits* in executable-chunk form, not behavior, with no structure, no prior state, and no sync guarantee with the image. The image won on liveness and lost on composability (no diff, merge, or reproducible build from text).

### Cited Findings
- The Smalltalk ChangeSet is "a transaction log that records source edits immediately after each operation"; "such a log can be explored to recover and replay the sequence of changes" after an interruption. Limitations: unstructured text (chunks of executable commands, not declarative records); only class/package/method definitions logged (refactorings and class modifications missing); mixed concerns and coarse granularity (adding an instance variable and adding a class look the same); prior states not stored. If the user doesn't save or the system crashes, "the log and image become desynchronised." Epicea (Pharo, 2013) adds a CodeChange event hierarchy with enough information to revert/redo, parent pointers, tags (author, timestamp, triggering event), replay, and branch-on-redo. — Dias, Cassou, Ducasse, "Representing Code History with Development Environment Events," arXiv 1309.4334 (2013) [F] https://ar5iv.labs.arxiv.org/html/1309.4334
- Pharo/Squeak by Example, chapter "In Smalltalk, You Can't Lose Code": recovery via the changes file after a crash is the standard workflow. [F listing] https://eng.libretexts.org/Bookshelves/Computer_Science/Programming_Languages/Book%3A_Pharo_by_Example_5.0_(Ducasse_Zagidulin_Hess_and_Chloupis)/08%3A_Sharing_Code_and_Source_Control/8.04%3A_In_Pharo_You_Cant_Lose_Code
- Kay's HOPL II account of Smalltalk (1993) [K] https://doi.org/10.1145/155360.155364 and Ungar/Smith Self (1987) [K] are the primary sources for the image model; Self's mirrors and dynamic deoptimization are the documented machinery for reconstructing first-order state from optimized code [K].

### Inferences
- Mapping to the Form: Smalltalk logged D for the *programmer's* events (edits) with no hash chain and no fixed initial state; the image was S but could be snapshotted out of sync with D. RCE's D logs the *program's* events with a hash chain and a fixed S0, which is the missing half [O].
- Why images lost: a snapshot of S is not canonical (it includes GUI state, timestamps, object identities), so two images are never equal and cannot be diffed; text won because text is canonical even when behavior is not — the opposite trade from the Lisps [O].
- The Smalltalk failure mode (log and image desynchronise on crash) is exactly the host-contract concern in RCE Appendix E (durable append, single admitter) [O, from README].

### Gaps
- No primary quantitative evidence on Smalltalk's commercial decline (market share, 1995–2000) was fetched; the Java-displacement story is widely stated but I did not locate a measured source.

## Key Question 4: Gradual typing — the cost of moving back from a compactified coordinate

### Takeaway
Re-expanding the type coordinate *soundly* in a dynamic language costs up to ~100x at typed/untyped boundaries (Takikawa et al. POPL 2016); JIT work recovers >90% of that (Pycket, OOPSLA 2017); the production answer (Racket 8.7, Nov 2022) is to offer three semantics — deep (sound, expensive), shallow (local shape checks), optional (free, enforces nothing) — i.e., to make the re-expansion a dial. Industry (TS, mypy, Sorbet) chose "optional/erasure" from the start; Elixir chose sound-with-`dynamic()`.

### Cited Findings
- Takikawa, Feltey, Greenman, New, Vitek, Felleisen, "Is Sound Gradual Typing Dead?" POPL 2016: 12 Typed Racket benchmarks, 2^n configurations per n-module program, 30 runs each; suffixtree (6 modules, 64 configs): typing the first module ≈88x slower, adding `structs` ≈104x, `main`/`ukkonen`/`lcs` ≈99–104x, fully typed 0.7x — the only acceptable point; thresholds N=3 "deliverable", M=10 "usable"; few configurations meet either; prior reports of ~10x (Reticulated Python) and 22x average (Safe TypeScript); conclusion "in the context of current implementation technology, sound gradual typing is dead." — [F via summary] https://blog.acolyer.org/2016/02/05/is-sound-gradual-typing-dead/ ; paper [K] https://doi.org/10.1145/2837614.2837630
- Bauman et al., "Sound Gradual Typing: Only Mostly Dead," PACMPL 1(OOPSLA) 2017: Pycket (RPython tracing JIT for Racket) "eliminates more than 90% of the gradual typing overhead" on the POPL 2016 benchmarks, via JIT + optimized chaperone/impersonator checks using hidden classes. — [F] https://scholarworks.iu.edu/dspace/items/131d8f23-1943-45ae-86c3-28a6a526f0e0
- Racket 8.7 (20 Nov 2022) introduced Shallow and Optional Typed Racket: Deep types compile to higher-order contracts at boundaries (guarantees "any module can depend on"); Shallow enforces "only local invariants in typed code" via shape checks; Optional "enforce nothing" at zero cost; Deep's cost described as "huge" in the larger examples. Based on Greenman, "Deep and Shallow Types for Gradual Languages," PLDI 2022. — [F] https://blog.racket-lang.org/2022/11/shallow-typed-racket.html
- Elixir: `dynamic()` is the gradual type; with it present types are checked at runtime, without it the system is static; inference milestones 1.18 (patterns) → 1.19 (all but guards) → 1.20 (complete); signatures later. — [F] https://elixir.hexdocs.pm/1.19/gradual-set-theoretic-types.html
- TypeScript's design goals explicitly list "apply a sound or 'provably correct' type system" as a non-goal. [K] https://github.com/microsoft/TypeScript/wiki/TypeScript-Design-Goals

### Inferences
- In atlas terms: de-compactifying a coordinate after the fact costs *boundary checks* proportional to the number of chart transitions (typed↔untyped crossings), not to program size — the overhead is holonomy around the typed/untyped loop. Fully typed (0.7x) and fully untyped (1x) are both cheap; mixtures are not [O from F].
- The 2016→2022 arc is the lineage discovering that the cheap option is to *declare* the coordinate (optional/erasure) rather than *enforce* it — which is the same choice as PEP 484 and TS. A Form that fixes types from the start never pays this [O].

### Gaps
- Exact percentages of deliverable/usable configurations and Greenman PLDI 2022 overhead tables were not retrieved.
- Reticulated Python and Safe TypeScript numbers are as reported second-hand in Takikawa et al.

## Key Question 5: Dynamic languages as LLM-preferred charts (2024–2026)

### Takeaway
Models produce correct Python more often than most other languages, and the measured cause is corpus volume, not dynamic typing itself; agents in 2026 spontaneously "prototype in Python" even when the target is another language. For a model-authored Form surface, this argues for a surface whose *notation* is Python-adjacent and whose *semantics* are fixed, with translated synthetic data (MultiPL-T style) to lift the low-resource target.

### Cited Findings
- MultiPL-T (OOPSLA 2024): fine-tuning on ~40–48k functions *translated from Python* (with test validation) lifts low-resource pass@1 by 1.5–3x (Racket 11.8→21.0 for StarCoderBase-15B; DeepSeekCoder-33B Racket 23.3→36.6; StarCoder2-15B 22.41→29.7); training longer on the natural low-resource corpus barely helps or hurts; self-instruct in the low-resource language fails because generated programs are buggy (4/5). — [F] https://arxiv.org/pdf/2308.09895
- Wu, Anderson, Guha 2026: across five models, agents "prototype in Python to avoid unfamiliar target languages," produce non-compiling code in unfamiliar languages, and revise already-passing solutions; token cost varies by language consistently across models. — [F abstract] https://arxiv.org/abs/2607.22807
- MultiPL-E 2022: performance "correlated with language popularity"; no overall type-annotation effect. — [F] https://arxiv.org/pdf/2208.08227

### Inferences
- A new Form surface is by definition a zero-resource language; the evidence says (a) its syntax should borrow the highest-resource habits (Python/JS), (b) its training data should be produced by *translation from Python with test-based validation* (the MultiPL-T recipe), and (c) its checker's refusals (RCE's named rules) are the test oracle MultiPL-T needed and lacked [O].
- The "prototype in Python" behavior suggests the practical transition map for model authorship is Python→Form, so the Python row's translation-IN route (generators/frames as state, no `eval`/reflection) defines the admissible Python subset [O].

- No 2025–2026 frontier-model per-language pass@1 table was fetched; the quantitative claims are from 2022–2024 open models.
- Token-cost multipliers per language are unavailable from the one peer-track source found.
