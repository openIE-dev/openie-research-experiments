# ML / typed-functional / proof-assistant lineage — one chart of the atlas

Frame used throughout: the Form P=(S,E,δ,D,λ). Coordinates: **S** state layout, **E** event alphabet, **δ** transition, **O** order/concurrency, **R** resource/energy, **T** trust/authority, **B** binding time, **I** intent/spec. Notation per row: `F` fixed by the language, `~` free (left to the program or runtime), `•` compactified to a point (the language has no vocabulary for it). "Into FSM" = cheapest known route to a first-order state machine; "Out" = route back; "Loss" = documented holonomy. The reference design's own exclusion of effect handlers is in spec/book/17-draft09.md F.2 of the repo (local clone): handlers break T2 (bound computed from call graph) and T3 (log would need the continuation).

Sourcing note: fetched this session = marked (fetched). Everything else cites the canonical DOI/URL of a primary paper or doc from established literature; treat any date I could not fetch as "well known, not re-verified today".

## Key Q0: the atlas rows (one per language)

### Takeaway
Every member fixes δ (a deterministic reduction relation) and compactifies R and I; they differ almost entirely on E (none vs. effect rows vs. abilities), O (none vs. monadic vs. handlers vs. BEAM), T (type abstraction / LCF kernel / capabilities) and B (none / staging / macros / elaboration). The only members that fix S, E, δ, λ the way the Form does are Elm's architecture, Bluespec's rules, and Unison/Dhall's content-addressed terms.

### Cited Findings (rows)

- **ISWIM (1966).** S• E• δF (SECD, applicative order) O F-sequential R• T• B• I•. Strict. No effect system (Landin's J-operator for control is the ancestor of continuations). No totality. No metaprogramming. Refused: machine-specific syntax, assignment as primary. Never implemented; "saved" by being the ancestor of every row below. Into FSM: the SECD machine *is* a first-order machine; Danvy derives it mechanically from an evaluator ("A rational deconstruction of Landin's SECD machine", 2004). Out: refunctionalize. Loss: names/sharing. — [Landin 1966, CACM](https://doi.org/10.1145/365230.365257); [Danvy 2004](https://doi.org/10.1007/11431664_4)
- **ML / Edinburgh LCF (1973–79).** S~ (refs) E• δF-strict O• R• **TF** (the abstract type `thm`: trust = type abstraction, the LCF kernel idea) B• I•. Strict; exceptions + refs untracked. Hindley–Milner inference proved principal-types (theorem). Refused: untyped tactics. Saved: HOL/Isabelle/Coq all descend from the LCF kernel discipline. — [Milner 1978, JCSS](https://doi.org/10.1016/0022-0000(78)90014-4); [Gordon, Milner, Wadsworth 1979, LNCS 78](https://doi.org/10.1007/3-540-09724-4)
- **Standard ML (1990 Definition; 1997 revision).** S~ E• δF (strict, left-to-right, specified by natural semantics) O• (concurrency absent; CML is an extension) R• TF via modules/opaque signatures B• (no macros, no staging) I•. Totality: none. Metatheory: the Definition is a formal semantics; type safety mechanized in Twelf for a large elaborated fragment (Lee–Crary–Harper 2007); **CakeML** (POPL 2014) is a verified compiler from an SML subset to 6 ISAs in HOL4, bootstrapped inside the logic, with verified parser and type inferencer (fetched). Killed: frozen Definition and no evolution process (HOPL IV account); saved as verification substrate (CakeML, Candle = verified HOL Light on CakeML; Isabelle→CakeML pipeline). Into FSM: CEK/CAM machines, Danvy correspondence; CakeML's own 8-IL pipeline is a mechanized witness. Loss: none proved for the verified fragment. — [MacQueen, Harper, Reppy HOPL IV 2020](https://doi.org/10.1145/3386336); [Lee, Crary, Harper POPL 2007](https://doi.org/10.1145/1190216.1190245); [CakeML POPL 2014](https://doi.org/10.1145/2535838.2535841); [cakeml.org](https://cakeml.org/) (fetched); [Candle ITP 2022](https://doi.org/10.4230/LIPIcs.ITP.2022.3)
- **OCaml (1996; OCaml 5.0, Dec 2022).** S~ E~ (since 5.0: effect operations are a user-declared alphabet, but **untyped**) δF-strict (argument order unspecified) O~ (domains + handlers; no static tracking) R• T via modules/first-class modules B: MetaOCaml staging (Taha–Sheard 1997; BER MetaOCaml) I•. ### Inferences
- The chart splits on how E is fixed: by monad type (Haskell), by effect row (Koka, old PureScript), by capability (Effekt, Scala CC, Roc platforms), by an untyped runtime alphabet (OCaml 5, Gleam/OTP), or by the architecture (Elm). Only the last gives S, E, δ, λ simultaneously, which is why Elm is the nearest historical neighbour of the Form.
- Binding time is the coordinate with the widest variance in this family (none → staging → macros → elaboration → type providers) and the least metatheory (no row has a proved-sound macro system except Lean's hygiene argument and MetaOCaml's typed staging).

## Key Q1: proved metatheory and TCB size

### Takeaway
Only three artefacts in the family have *mechanized, end-to-end* trust: CakeML (verified compiler for an SML subset, self-bootstrapped), MetaCoq's verified checker for a large fragment of Coq, and the Lean-in-Lean checker (Lean4Lean, partial proofs). Everything else is kernel-by-discipline (LCF-style small kernels) plus paper proofs of cores.

## Key Q2: algebraic effects vs monads vs capabilities — what compiles to a total deterministic step with a log

### Takeaway
All three compile to pure λ-terms (monads trivially; handlers via evidence passing; capabilities via capability-passing style), so *determinism* is never the obstacle; the obstacle is that multi-shot resumption clones the continuation (and with it the captured state), which breaks ownership/bounds, not loggability. Industry converged on one-shot (OCaml 5, WasmFX).

### Cited Findings
- Evidence passing: scoped-resumption handlers translate to plain λ-calculus, "fully sound and coherent"; tail-resumptive operations run in place with no context capture; handler lookup becomes constant-offset indexing — [Xie & Leijen ICFP 2020](https://www.microsoft.com/en-us/research/publication/effect-handlers-evidently/) (fetched)
- Generalized evidence passing: multi-prompt delimited control → monadic translation to λ-calculus → C; benchmarked against Multicore OCaml, Ev.Eff, libhandler — [Xie & Leijen 2021](https://www.microsoft.com/en-us/research/publication/generalized-evidence-passing-for-effect-handlers/) (fetched)
- OCaml 5: one-shot by construction, second resume raises; chosen because concurrency never needs multi-shot and copying fibers is "unnecessary and inefficient"; no effect safety — [arXiv 2104.00250](https://arxiv.org/abs/2104.00250) (fetched)
- WasmFX (WebAssembly effect handlers) also one-shot — [Phipps-Costin et al. OOPSLA 2023](https://doi.org/10.1145/3622814)
- Effekt: capability-passing style; second-class functions prevent capability escape — [OOPSLA 2020](https://pl.cs.uni-tuebingen.de/publications/brachthaeuser20effects/) (fetched)
- Handlers have a first-order abstract-machine semantics (CEK with handler frames / generalised continuations) — [Hillerström & Lindley TyDe 2016](https://doi.org/10.1145/2976022.2976033); [Hillerström, Lindley, Atkey JFP 2020](https://doi.org/10.1017/S0956796820000040)
- Monads: Wadler 1992 / Peyton Jones–Wadler 1993 give the canonical "effects as a pure state-passing term" — [POPL 1992](https://doi.org/10.1145/143165.143169)
- Multi-shot handlers are the standard encoding of nondeterminism (Eff origin) — [Bauer & Pretnar 2015](https://doi.org/10.1016/j.jlamp.2014.02.001)

### Inferences
- **Strongest counterargument to "multi-shot cannot be logged as events":** after evidence/CPS translation plus Reynolds defunctionalization, a continuation is first-order data; a multi-shot handler is then a deterministic fold over a tree of resumptions, and the log needs only the *external* events plus, at most, the handler's branch choices (which are program-determined, hence replayable). So T3 ("the log would need the continuation") is answerable. What is *not* answerable is T2 and ownership: each extra resume duplicates the captured state, i.e., aliasing of S by another name, and the number of resumes is data-dependent so no call-graph bound exists. The honest grounds for the exclusion are resource/ownership, not loggability — and they coincide with the engineering grounds OCaml 5 and WasmFX gave for one-shot.
- One-shot, tail-resumptive handlers (the Koka fast path) are observationally a first-order state machine already; admitting *that* fragment would not break T2/T3.

### Gaps
- No paper found that proves equivalence between an effect-handler program and an event-logged replay in the Form's sense; the inference above is a synthesis.

## Key Q3: what totality cost

### Takeaway
Totality by default survives only where the program is small (config: Dhall) or the user is a prover (Agda, Coq, Lean); every general-purpose row made it opt-in (Idris, Koka's `div`, F\* `Dv`) or provided escape hatches, and the one general-purpose fully-total design (Turner 2004) was never adopted.

### Cited Findings
- Dhall: recursion is a type error; well-typed terms always terminate; "finite does not mean fast" — [Dhall safety](https://docs.dhall-lang.org/discussions/Safety-guarantees.html) (fetched)
- Agda: termination/coverage checking default, `--safe` closes the escapes — [Agda docs: safe mode](https://agda.readthedocs.io/en/latest/language/safe-agda.html)
- Idris 2: totality per definition / `%default` directive — [Idris 2 docs: totality](https://idris2.readthedocs.io/en/latest/tutorial/theorems.html#totality-checking)
- Koka: `div` effect marks divergence; absence = total — [Koka book](https://koka-lang.github.io/koka/doc/book.html)
- McBride: partiality as a monadic effect loses nothing ("Turing-completeness totally free") — [MPC 2015](https://doi.org/10.1007/978-3-319-19797-5_13)
- Turner's total FP proposal: data/codata split, no ⊥ — [JUCS 2004](https://doi.org/10.3217/jucs-010-07-0751)

### Inferences
- The cost is not expressiveness (McBride's result) but *checker friction*: structural termination is semi-decidable and rejects valid programs, so every adopter added measures (`decreases`), sized types or escapes. The Form's "written termination measures" (repo F) is the Dafny/F\*/Isabelle `function`-package choice, which has the best adoption record of the options.

### Gaps
- No quantitative adoption data (user counts) for Dhall or Agda was found; qualitative only.

## Key Q4: content-addressed and canonical-form attempts

### Takeaway
Two shipped systems hash *meaning*: Unison (SHA3-512 of the name-free syntax tree, dependencies by hash) and Dhall (SHA-256 of the β-normal form). Provers hash for *sharing* (hash-consing), not identity.

### Cited Findings
- Unison: hash of syntax tree, names as metadata, deps by hash, typecheck-once cache in the codebase format, two library versions coexist — [the-big-idea](https://www.unison-lang.org/docs/the-big-idea/) (fetched)
- Dhall: hash over normal form, refactor-stable, meaning-sensitive including transitive imports — [Dhall safety](https://docs.dhall-lang.org/discussions/Safety-guarantees.html) (fetched)
- Hash-consing in ML/Coq: the type-safe modular technique used in Coq's kernel — [Filliâtre & Conchon 2006](https://doi.org/10.1145/1159876.1159880)
- Lean: `#eval` executes compiled code, kernel checks terms; `leanchecker` exists precisely because the environment can be forged by metaprograms — [lean4checker](https://github.com/leanprover/lean4checker) (fetched)

### Inferences
- Unison's "names are metadata" is the same move as the repo's name-free content-hash order (FORM.md law 2, per SURFACE.md). Dhall shows the price: a canonical form requires a normalizer in the TCB and β-normalization can be exponential ("finite ≠ fast").

### Gaps
- Dhall's CBOR binary encoding (the thing actually hashed) is in the standard but the fetched page did not mention it; not re-verified.
