# The 2024–2026 field of languages and IRs for agent authorship — competitive and design input for the Reality Code Engine (RCE)

Scope: as of 22 October 2026. "Fact" items are cited; items marked [opinion] are the cited author's or this researcher's judgement. Adoption signals from GitHub stars are flagged as weak/anecdotal throughout. "RCE" below always means the Reality Code Engine (research.openie.dev, github.com/openIE-dev/rce), never remote code execution.

## Grounding: what RCE is (from the paper and the local clone)

### Takeaway
RCE is a small spec-defined language whose every program has one meaning, a state machine ("Form") with a hash-chained event log; examples inside `intent` blocks are part of the program and are checked at admission; the surface is designed to take "the best of Rust, Zig, Go, Swift and Python". The paper's section 3.7 explicitly says the recurrence of its choices in 42 catalogued agent languages is "an observation that the choices recur", "not evidence that they are correct", and makes no comparison with them — this note supplies that comparison.

### Cited Findings
- Paper abstract: "a program is written once as a state machine, called a Form, and code in other languages is generated from it"; measurements on 10,000 Forms and public bug datasets; falsifiability conditions stated — [RCE paper](https://research.openie.dev/papers/rce/)
- Section 2 design axes: (1) energy per correct result, (2) entropy resolved at run time / determinism, (3) verification strength, (4) reuse and compounding, (5) model reliance. "RCE writes the meaning once, in one canonical Form"; among equivalent forms "the cheapest correct one runs" — [RCE paper](https://research.openie.dev/papers/rce/)
- Section 3.7: catalogue read 13 Oct 2026 lists 42 languages in syntactic, verification and orchestration camps; mechanically checked contracts, hash-chained logs, deterministic replay and one canonical form "appear in the catalogue's descriptions of other projects"; "this paper makes no comparison with those projects" — [RCE paper](https://research.openie.dev/papers/rce/)
- Mechanisms: each log entry records the event, previous hash and SHA-256 state hash (tampering "breaks the chain"); Proposition 4 / Theorem T3: replay reproduces every hash and output if the transition reads no wall clock, orders updates without names and logs every input; refused event leaves state unchanged (T8); canonical serialization is injective so distinct Forms have distinct shape hashes; promotion gate = replay of recorded inputs + shadow run with coverage bound + output schema check + Kani proof certificate — [RCE paper](https://research.openie.dev/papers/rce/)
- README (draft 0.7): three plain-words guarantees — same answer on every computer; every program finishes (bounded loops, structural recursion); mistakes caught before run (use-after-move, missing case, failing example refuse the program and name the rule). `example` lines are part of the program: "if either one did not hold, `rce check` would refuse the file." Commands: check/test/run/trace/emit (form, rust, python, js, scala)/fmt/lsp. Lean 4 model in `spec/lean/`; tree-sitter second parser; grammar-level fuzzer. Versions 0.6–0.8 add `par`, budgets, LVars, sessions, supervisors, `Text[Html|Url|Sql|Json]`, `Secret[τ]`, `Cap[A]`, `Guarded[τ,A]` — local file `/tmp/claude-0/-home-claude/a51bc2e6-10c5-5671-9c6b-8af67db8621d/scratchpad/repos/rce/README.md`
- SURFACE.md design goal: "the best of Rust, Zig, Go, Swift and Python in one surface, with no garbage collector, memory safety by construction, native code at the speed of hand-written C or Rust, and the shortest path from human intent to a complete program." Table maps Rust ownership/traits/match, Zig comptime/arenas/error unions, Go spawn/chan/select, Swift value types/protocols/actors, Python indentation, plus RCE-original `intent` blocks ("examples become checks at the gate") — local file `.../repos/rce/SURFACE.md`
- spec/LANGUAGE-REVIEW.md (2026-10-12) already records what RCE took from Rust/Go/Python/Mojo/Zig/Haskell: second-class borrows instead of lifetimes; `τ ! ε` + `try` from Zig; no unwinding; explicit `extern` trust boundary from Rust 2024 — local file `.../repos/rce/spec/LANGUAGE-REVIEW.md`

### Inferences
- RCE's own prior review covers the *mainstream* languages well; what it lacks is a comparison against the *agent-language* cohort and the durable-execution runtimes, which is where its hash-chain/replay/contract choices actually have peers.

### Gaps
- The paper's final ~10k characters were not read (page over 100k chars); any late-section comparisons there are not reflected.

## KQ2. Notable catalogue entries assessed in depth (what each got right / wrong)

### Takeaway
The most instructive entries for RCE are Vera (mandatory contracts, honest proven-vs-runtime split, JSON-first toolchain, but a saturated self-benchmark), Zero (structured diagnostics with typed repair plans, "humans read the message, agents read the JSON"), Tacit/Unison (AST as source of truth, content-hashed definitions, names as metadata), NanoLang (mandatory shadow tests per function, Coq-proved core, bootstrap), Boruna (hash-chained evidence bundles + deterministic replay + VM-enforced effects — the closest runtime analogue to RCE's log) and Codong (one canonical operation per task, measured token wins).

### Cited Findings
- **Vera** (v0.1.9, Aug 2026; 205 releases, ~2,400 commits, 9,382 tests at 95% coverage): grammar rejects functions without `requires`/`ensures`/`effects`; three-tier discharge (Z3 decidable, Z3+hints [unimplemented], compiled runtime check); `vera verify --json` reports `tier1_verified` vs `tier3_runtime` counts; De Bruijn slot references instead of parameter names (`@Int.0`) citing Wang et al. arXiv:2307.12488 and Le et al. arXiv:2510.03178; `<DB>` effect makes SQL injection a compile error (E207) via literal query provenance without a solver; stable error codes E001–E702; LSP methods `vera/speculativeEdit`, `vera/strengthenContract` report whether an edit keeps/breaks proofs. Self-stated wrong/unfinished: Tier 2 missing; refinement facts lost through ADT fields; a naming bug class appeared anyway (six subsystems disagreed on type aliases); no package registry; VeraBench saturated, single runs, raw results not checked in — [agentlanguages.dev/vera](https://agentlanguages.dev/languages/vera/)
- **VeraBench**: 60 problems, five tiers, nine models, three providers, Vera v0.1.8; Vera avg 98.7% vs Python 96.7% vs TypeScript 99.7%; the "93%" figure is Claude Opus 4.8's Vera-mode score, the lowest; caveats: single run, no pass@k, 1.7 pp per problem, TypeScript at 100% in 8/9 configs (saturated), weak specs on some problems, Python gap partly a grading issue (#121) — [vera-bench](https://github.com/aallan/vera-bench); the essay's "93% correctness with zero training data, matching Python" is therefore the worst-case Vera number, not the headline — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)
- **Zero** (Vercel Labs, v0.1.1 15 May 2026, Apache-2.0, ~3.3k stars at cataloguing, 5.4k+ on 19 Oct): no LLVM, direct ELF/Mach-O/PE + Wasm emitters, sub-10 KiB binaries as a load-bearing goal; `world: World` passed explicitly (no hidden global I/O); `raises`/`check` explicit errors; `zero check --json` → stable code (e.g. `NAM003`), message, line, typed `repair`; `zero fix --plan --json` returns an edit plan "rather than advice"; `zero skills get zero --full` returns guidance pinned to the installed compiler version; README calls it a "pre-1 experiment", run only in isolated environments. Thesis: "the bottleneck in agentic coding is the channel between compiler and agent, not the language"; slogan "Humans read the message. Agents read the JSON." Determinism not discussed — [agentlanguages.dev/zero](https://agentlanguages.dev/languages/zero/)
- **Boruna** (v0.2.0, Apr 2026, 34 commits, 9-crate Rust workspace, 557+ tests, 0–5 stars): per-step `.ax` files with effect signatures like `!{time}`; VM refuses a step performing an undeclared effect; effects reach the VM as values so each is recorded and replayed; every step writes inputs/outputs/model responses/approvals into a Merkle-chained evidence bundle; re-running against the bundle is "meant to produce bit-identical results"; human approval gate is a first-class primitive; MCP server exposes ten tools (draft, dry-run, validate, inspect evidence, trigger approval). Catalogue notes claims are the project's own, not independently verified — [agentlanguages.dev/boruna](https://agentlanguages.dev/languages/boruna/)
- **NanoLang** (v3.3.7 Apr 2026, 51 releases, ~2,156 commits, 629 stars, Apache-2.0, bootstrap 100%): every function must carry a `shadow` test block or the compiler refuses it ("I refuse to compile a function unless you provide a shadow test block"); NanoCore proved in Coq/Rocq ≥9.0: 6,170 lines, 193 theorems, zero axioms/Admitted — preservation, progress, determinism, big/small-step equivalence, evaluator soundness vs fuel-based reference interpreter; effects, async, FFI, VM, codegen out of proof scope; targets C and Wasm (parity), LLVM/PTX/RISC-V (no parity). Author: "used in production by exactly one person, who also wrote it." No empirical LLM-authorship results reported — [agentlanguages.dev/nanolang](https://agentlanguages.dev/languages/nanolang/)
- **Tacit** (v0.7.7 19 May 2026, ~90 ADRs, 237 commits, 3 stars): "The AST is the source of truth"; `.tac` is a byte-exact canonical projection; names/type hints in a `.tacd` JSON sidecar; definitions identified by BLAKE3 of canonical text so renames keep identity and imports pin hashes not versions; De Bruijn indices; typed `Hole` nodes keep tools working on partial programs (ADR 0040); effects `IO/Alloc/Mut/Div` mandatory at unit exports, inferred locally; `tacit-toolchain.toml` pins toolchain/primer/stdlib hashes and refuses mismatches; `tacit primer --section` for selective disclosure into a context window — [agentlanguages.dev/tacit](https://agentlanguages.dev/languages/tacit/)
- **Codong** (v0.1.3 28 Mar 2026, 92 commits, 67–73 stars, Go): one function per task in nine bundled modules (`http.get`, `db.connect`, `json.parse`); errors carry stable code, message, fix suggestion, retry boolean; compact single-line error mode (~39% fewer error-output tokens, self-reported); self-run "arena" on Posts-CRUD with Claude Sonnet 4: 955 tokens Codong vs 1,867 Python, 1,710 JS, 4,367 Java (one workload, not independent); `SPEC_FOR_AI.md` pairs CORRECT/WRONG examples per rule for system prompts — [agentlanguages.dev/codong](https://agentlanguages.dev/languages/codong/)
- **MoonBit**: LLM4Code@ICSE 2024 paper (Fei, Zhang, Zhang, Liu — IDEA; Wang — SYSU) introduces "a real-time, semantics-based sampler to guide the inference process of language models" to produce code free of syntax and obvious type errors; the page reports "notable improvement" but no metrics — [ICSE 2024 LLM4Code](https://conf.researchr.org/details/icse-2024/llm4code-2024-papers/9/MoonBit-Explore-the-Design-of-an-AI-Friendly-Programming-Language); the catalogue essay calls it "the only peer-reviewed academic work he found in the space" [opinion] — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)
- **Quasar** (Penn, paper): 42% execution-time reduction and 52% fewer user-approval interactions on a VQA agent, via auto-parallelisation, conformal reliability bounds and approval-gated security (figures as relayed by the essay) — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)
- Convergence on *intent as program text*: Aver ("functions carry intent, declared effects, and verify blocks"), Pact ("intent blocks, pipelines, and explicit effects"), Prove ("intent-first language with refinement types and contracts"), reqlan ("requirement files linked to symbols and tests; broken links fail the checker"), NanoLang (mandatory shadow tests) — [agentlanguages.dev](https://agentlanguages.dev)
- Convergence on *one canonical form*: Codong (one operation per task), Tacit (one serialisation per AST), Zero ("one obvious path"), X07 (JSON AST only), Magpie (SSA as surface), NERD ("one obvious way") — [agentlanguages.dev](https://agentlanguages.dev); [Zero entry](https://agentlanguages.dev/languages/zero/)
- Convergence on *capabilities/effects as values*: Mog (host-granted capabilities), Zero (`world`), AILANG (IO/FS/Net/Clock/AI granted per run), Vera (ten typed effects incl. `<Inference>`), Boruna (VM-enforced effect signatures) — [agentlanguages.dev](https://agentlanguages.dev); [Vera entry](https://agentlanguages.dev/languages/vera/)

### Inferences
- The field has not yet produced an entry that combines all of: (a) one canonical injective form, (b) hash-chained log with proved replay, (c) examples/tests as admission gate, (d) mechanised metatheory, (e) multi-target emission. Boruna has (b) at the runtime level without (a)/(d); NanoLang has (c)/(d) without (a)/(b); Tacit has (a) without (b)/(c); Vera has contracts and a JSON toolchain without (b). RCE's README claims all five; that combination is its differentiator, provided the Lean model's scope is stated as candidly as NanoLang states its NanoCore scope.
- Every mature entry (Vera, Zero, Tacit, Codong, Vow) ships a machine-readable diagnostics contract: stable error codes, JSON output, a repair plan, and a version-pinned skill/primer. RCE's `rce check` "names the rule that was broken"; the comparable artefact is a stable rule-code registry + `--json` + a `rce explain RULE` + a `rce fix --plan`. This is table stakes in this cohort, not differentiation.
- Vera's "naming bug class appeared anyway" is a cautionary data point against the De Bruijn/no-names bet: removing names from the language did not remove naming defects from the toolchain.

### Gaps
- No entry (including RCE's paper, per its own 3.7) publishes a head-to-head LLM-authorship comparison between agent languages beyond VeraBench's Vera/Aver/AILANG/Python/TypeScript, and that benchmark is saturated. Independent per-language agent-correctness data for any 2026 agent language does not exist as of this search.
- Mog, Aver, Hale, Thermite, X07 and Magpie were read only via the catalogue index, not their own pages.

## KQ3. Mainstream and research languages 2024–2026: what changed and what it teaches

### Takeaway
The mainstream signal is consistent: ownership without first-class lifetimes is now a live design track (Mojo origins/argument conventions, Hylo mutable value semantics); function colouring is being removed by passing an I/O capability (Zig 0.16 `std.Io`); strict concurrency that ships before ergonomics are ready gets rolled back (Swift 6 → 6.2 "approachable concurrency"); and content-addressed code (Unison) remains the strongest prior art for RCE's canonical-form/hash identity. LLMs verify Dafny far better than Verus or Lean.

### Cited Findings
- **Mojo**: Modular open-sourced the whole language (compiler + tooling) under Apache 2.0 on 18 Aug 2026, about three weeks after Qualcomm completed its acquisition of Modular; Mojo 1.0 shipped with Modular 26.5 — [RuntimeWire, 19 Aug 2026 (upd. 14 Oct)](https://runtimewire.com/article/chris-lattner-open-sources-mojo-qualcomm-modular). Ownership: one owner per value; argument conventions declared in signatures — default read-only borrow with no call-site sigil, `mut`, `var` (take ownership; caller transfers with `^`), `ref` (parametric mutability), `out`, `deinit`; the lifetime checker prevents destruction while references are outstanding; exclusivity violations (same value as `mut` and immutable) are rejected; register-passable trivial types exempt — [Mojo manual: ownership](https://mojolang.org/docs/manual/values/ownership/)
- **Hylo** (Dimi Racordon, EPFL LAMP, PLSS@ECOOP 4 Jul 2025): "built on mutable value semantics for safety and efficiency"; after ~4.5 years "its overall design has solidified into a coherent system offering promising results"; still in development; talk explicitly covers "the challenges of keeping the project active and its community engaged" — [ECOOP 2025 PLSS](https://2025.ecoop.org/details/plss-2025-papers/12/Designing-Hylo-a-programming-language-for-safe-systems-programming)
- **Zig 0.16.0** (14 Apr 2026, 244 contributors, 1,183 commits): `std.Io` is an abstract interface like `Allocator` (implementations `Io.Threaded` default, `Io.Evented` M:N experimental, `Io.Uring`, `Io.Kqueue`, `Io.Dispatch`, `Io.failing` for tests); "sync and async functions share the same signature. Only the passed `Io` differs, so async does not spread through a codebase the way `async fn` does in Rust"; `main(init: std.process.Init)` supplies allocator, Io, arena, environ; global `std.os.environ` removed; `GenericReader`/`AnyReader`/`FixedBufferStream` removed (0.15 "writergate" baseline); new self-hosted ELF linker; LLVM 21 — [tproger, Zig 0.16](https://tproger.ru/news/vywel-zig-0-16-di-v-main-i-o-kak-interfejs-i-async-bez-raskra)
- **Zig principles**: "If Zig code doesn't look like it's jumping away to call a function, then it isn't" (no hidden control flow); "hands-off approach when it comes to heap allocation" (no hidden allocations; allocating std APIs take an `Allocator`); "Zig has no macros yet is still powerful enough…"; large feature sets in C++, Rust and D "distract from the application itself" — [ziglang.org: Why Zig](https://ziglang.org/learn/why_zig_rust_d_cpp/)
- **Swift 6 → 6.2**: WWDC25 "approachable concurrency" (InfoQ 3 Aug 2025) infers isolated conformances and defaults `nonisolated async` to `nonisolated(nonsending)` (run on caller's executor), ships with "main actor by default"; motivation per InfoQ's summary of Swift forums: adoption of Swift 6 strict concurrency "caused many issues", Swift "moved too fast before the language, ecosystem, and documentation were ready" and "went too far for mobile apps" — [InfoQ](https://www.infoq.com/news/2025/08/swift62-approachable-concurrency)
- **Carbon**: roadmap says end of 2026 is "the *soonest* that 0.1 could realistically be ready to ship"; adding a memory-safety design pushes it out "by at least a year"; 2025 objectives: C++ interop for most non-template APIs, and a Rust-like compile-time temporal/mutation safety design; 1.0 "beyond 2028" — [Carbon roadmap](https://github.com/carbon-language/carbon-lang/blob/trunk/docs/project/roadmap.md)
- **Rust 2024 edition**: Rust 2024 edition project goal page (stabilised in Rust 1.85, Feb 2025 per RCE's LANGUAGE-REVIEW citing the Edition Guide); `unsafe extern` and `unsafe_op_in_unsafe_fn` by default mark every unchecked operation where it occurs — [Rust 2024 Edition goal](https://goals.rust-lang.org/2024h2/Rust-2024-Edition.html); [local LANGUAGE-REVIEW.md §2.1]
- **Unison**: each definition identified by a 512-bit SHA3 hash of its syntax tree with names as separate metadata; consequences: no builds (typecheck results cached forever), no dependency conflicts (two versions coexist), free renames, typed durable storage, code relocation across machines; tradeoffs: duplicate definitions accumulate, distributed programming "remains hard", the structured approach "gives up" much of the text-tool ecosystem — [Unison: the big idea](https://www.unison-lang.org/docs/the-big-idea/)
- **Verse** (Epic; ICFP/SPLASH 2025 REBASE talk by Saam Barati, 18 Oct 2025): multi-paradigm "functional, logic, object oriented, imperative, and transactional"; AutoRTFM (Clang fork + runtime) makes "most of Unreal Engine's C++ code transactional"; new from-scratch VM runs Verse 5x faster than the old one — [ICFP/SPLASH 2025](https://conf.researchr.org/details/icfp-splash-2025/rebase-2025-papers/4/On-creating-a-virtual-machine-for-Verse-a-language-for-programming-in-a-shared-real-)
- **Gleam**: 1.0 on 4 Mar 2024 (Louis Pilfold); 1.14.0 on 25 Dec 2025; Result-type errors, immutable data, ADTs + pattern matching, no null, no implicit conversions — [Wikipedia: Gleam](https://en.wikipedia.org/wiki/Gleam_(programming_language))
- **Vericoding benchmark** (Bursuc … Tegmark, 26 Sep 2025): 12,504 formal specs (Dafny 3,029; Verus/Rust 2,334; Lean 7,141; 6,174 new); off-the-shelf LLM success: Dafny 82%, Verus 44%, Lean 27%; adding NL descriptions "does not significantly improve performance"; pure Dafny verification rose from 68% to 96% over the prior year — [arXiv 2509.22908](https://arxiv.org/abs/2509.22908v1)
- **Durable-execution runtimes** (Particula Tech, 25 May 2026): Temporal/Inngest/Restate all journal each side-effecting step and re-execute code from the top on recovery with journaled steps returning saved results; workflow code must be deterministic — `Date.now()`/`Math.random()`/network must sit inside a step; LLM outputs recorded once and never re-called; failure modes: non-deterministic workflow code diverges on replay; Temporal history saturates (~10K events / 10 MB soft, ~50 MB hard) forcing claim-check storage; crash between external call and journal write can double-execute a side effect (idempotency keys) — [Particula Tech](https://particula.tech/blog/durable-execution-ai-agents-temporal-inngest-restate)
- **Config DSLs** (Pi Stack, 9 Oct 2026; star counts are the author's): CUE v0.17.1, 6,280 stars, "types and values are the same thing", non-Turing-complete; Dhall 1.42.2, 4,487 stars, total, imports pinned by semantic hash, "nothing in a Dhall file can hang" but unfriendly syntax/errors and small ecosystem; Pkl 0.32.1, 11,542 stars, Turing-complete with no termination guarantee, fastest-moving — [Pi Stack](https://www.pistack.xyz/posts/2026-10-09-cue-vs-dhall-vs-pkl-configuration-languages-2026/)
- **BAML** (Boundary, 13 Aug 2024): a prompting DSL with "typescript-like definitions" replacing JSON schemas; Schema-Aligned Parsing replaces `JSON.parse` and deliberately avoids JSON mode/constrained generation; self-reported BFCL: small models with BAML within <2% of gpt-4o structured output, "2-4x faster" than FC-strict; cites "Let Me Speak Freely" that schema constraints "degrade in average performance" — [BAML blog](https://boundaryml.com/blog/sota-function-calling)

### Inferences
- Zig 0.16 and Mojo independently validate RCE's SURFACE choice of capability-passing over function colouring and of ownership by argument convention rather than lifetime parameters. RCE's "second-class borrows" (LANGUAGE-REVIEW §2.1) is in the same family as Hylo's mutable value semantics and Mojo's conventions.
- Swift 6's rollback is the clearest 2025 evidence that "contracts always on" must ship with the ergonomics to satisfy them, or users route around the checker. For RCE, the analogue is the admission gate: refusal must come with a repair path (see Zero), not just a rule name.
- The Dahll/CUE/Dhall data show a totality guarantee (every program finishes) is accepted by users only when syntax and diagnostics are friendly; Dhall has the strongest guarantee and the weakest adoption of the three [inference from one source].
- Temporal's history-saturation problem is the operational risk for any "log is the database" design (RCEdb). The log must have a compaction/snapshot story with the same hash guarantees, or replay cost grows without bound.
- Vericoding data suggest LLMs discharge *auto-active* contract languages (Dafny-style) far better than proof-assistant languages (Lean); RCE's contract surface should look like Dafny's `requires/ensures` with decidable predicates (which `type R = τ where p` already is), and the Lean proofs should stay on the spec side, never required of the author.

### Gaps
- No reliable 2025–2026 status found for Koka, Roc, Bend/HVM2, Jai, Austral, Vale; searches returned noise. Treat them as unverified in this note. Lean 4 "as a language" (not as prover) likewise not covered beyond the vericoding numbers.
- Rust 2024 edition details come from RCE's own review plus the goals page, not from a fresh read of the Edition Guide.
- LangGraph/DSPy/Pydantic-AI determinism/checkpointing specifics not fetched from primary sources (search returned only secondary blogs); no claims made.

## KQ4. Empirical results: which syntaxes LLMs generate correctly, token efficiency, low-resource effects, constrained decoding

### Takeaway
Measured evidence says: (1) new languages pay a large low-resource penalty unless taught in-context or via synthetic translation data; (2) agents in unfamiliar languages burn tokens on non-compiling retries and Python prototyping; (3) formatting whitespace is ~25% of input tokens with no accuracy cost when removed; (4) grammar-only constrained decoding is insufficient — semantic/projectional constraints add 13–25 points of validity; (5) format restrictions on *reasoning* output hurt. Nothing measured yet shows that a *new syntax* beats a known one for agents once in-context docs are provided.

### Cited Findings
- MultiPL-T (Cassano et al., OOPSLA2 Oct 2024): StarCoderBase-15B pass@1 30.6 on Python vs Racket 11.8, R 10.2, OCaml 6.9, Julia 21.1, Lua 26.6; cause: The Stack has ~64 GB Python vs ~1 GB OCaml; fine-tuning on test-validated translations lifts OCaml 6.9→19.9, Racket 11.8→21.0, R 10.2→17.3, Julia 21.1→35.2, Lua 26.6→31.0 — [arXiv 2308.09895](https://arxiv.org/pdf/2308.09895)
- "No Silver Bullet" (Giagnorio, Martin-Lopez, Bavota; ICPC 2025): on R and Racket across six LLMs, in-context learning "always helps, but with different magnitudes" and becomes more effective with model size; fine-tuning best for small models; very large LLMs "may deteriorate their performance on low-resource languages when fine-tuning is performed" — [arXiv 2501.19085](https://arxiv.org/abs/2501.19085)
- "Tokenmaxxing" (Wu, Anderson, Guha; arXiv 2607.22807, 2026): five agent models on Python, Java, Rust, OCaml with difficulty controlled; "stark and consistent" per-language token differences; agents "repeatedly produce non-compiling code in unfamiliar languages, revise solutions that already pass, plan in code comments, invent test inputs instead of trusting provided tests, and prototype in Python" — [Khoury page](https://www.khoury.northeastern.edu/~arjunguha/main/papers/wu-tokenmaxxing.html)
- "Hidden Cost of Readability" (Pan, Sun, Zhang, Du, Lo; 19 Aug 2025): removing formatting cuts input tokens ~24.5% avg (Java ~34.9%, C++ 31.1%, C# 25.3%, Python 6.5%); Pass@1 drop never above 4.2% and not significant; GPT-4o Python rose 66.4→71.5% unformatted; output tokens fell only ~2.5% unless prompted (then ~27% on Java/C++/C#) — [arXiv 2508.13666](https://arxiv.org/pdf/2508.13666)
- Token Sugar (Sun, Yang, Du, Yang, Li, Lo; 9 Dec 2025): 799 reversible pattern→shorthand pairs; up to 15.1% fewer source tokens and 11.2% fewer generated tokens with Pass@1 "nearly identical" — [arXiv 2512.08266](https://arxiv.org/abs/2512.08266)
- "Let Me Speak Freely?" (Tam et al., Aug–Oct 2024): "a notable drop in reasoning ability under format restrictions"; stricter constraints → larger drops on reasoning tasks — [arXiv 2408.02442](https://arxiv.org/abs/2408.02442)
- Projectional Decoding (Chen, Hernández López, Babikian; FSE Companion Jul 2026): grammar-only (LLGuidance) vs grammar+semantic masking on CLEVR with Qwen3: semantic validity 48.7→73.7 (4B), 61.0→79.7 (8B), 58.3→73.3 (14B); accuracy 28→36, 37.3→40, 36.7→37.3; overhead 1.1–1.5x; semantic guidance "does not reach 100% validity" — [arXiv 2605.30054](https://www.alphaxiv.org/abs/2605.30054.md)
- Grammar-constrained decoding tooling: Grammar-Aligned Decoding (NeurIPS 2024) and "Flexible and Efficient Grammar-Constrained Decoding" (ICML 2025) exist as the reference methods — [NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/2bdc2267c3d7d01523e2e17ac0a754f3-Abstract.html); [ICML 2025](https://proceedings.mlr.press/v267/park25l.html) (abstracts not fetched; cited for existence only)
- Codong self-benchmark (one task, Sonnet 4): 955 tokens vs Python 1,867 — [Codong entry](https://agentlanguages.dev/languages/codong/); Vera reports flagship models write Vera at ~93–100% with zero training data when given the SKILL.md/primer — [vera-bench](https://github.com/aallan/vera-bench)
- Catalogue author [opinion]: syntactic-camp bets are misdirected because failures are "errors of intent and coherence at scale, not tokenization errors" — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)

### Inferences
- The low-resource penalty is real but closable: VeraBench (zero training data, 98.7%) and MultiPL-T both show that either a dense in-context spec/primer or test-validated synthetic translations recover most of the gap. For RCE this means the checked example corpus (`spec/examples/`, `rce-examples`, the Book) doubles as a fine-tuning/few-shot corpus, and `rce emit` can mass-produce *test-validated translations* from RCE to Rust/Python/JS/Scala — exactly the MultiPL-T recipe, but in reverse (foreign→RCE translations validated by `rce test`).
- Whitespace studies cut against Python-style indentation blocks as a token-efficiency choice: Python keeps only ~6.5% headroom because its syntax *is* whitespace, so RCE's indentation surface forfeits the free 25–35% input savings that brace languages can strip. Counter-consideration: output-side savings are small anyway (~2.5%) and readability for human review matters; the trade is defensible but should be stated as a trade.
- Tokenmaxxing's "invent test inputs instead of trusting provided tests" is a direct argument for examples-as-admission-gate: if the examples are the program and the checker runs them, the agent cannot substitute its own oracle.
- Projectional decoding's numbers support RCE's claim that a type checker (semantic), not a grammar (syntactic), is the sampler that matters; the RCE checker + LSP is the natural "partial model" for such a decoder, which MoonBit's 2024 paper attempted and did not quantify.

### Gaps
- No paper found that compares *novel* syntaxes head-to-head for LLM authorship under identical in-context budgets. VeraBench is the only such attempt and is saturated.
- Tokenmaxxing numeric per-language figures not extracted (PDF not fetched).

## KQ5. Independent convergence on RCE's choices and what those projects learned

### Takeaway
Each RCE mechanism has at least one independent peer: hash-chained logs (Boruna), deterministic replay (Boruna, Temporal/Restate/Inngest journals, AILANG, Lumen's compile-time determinism checks), contracts always on (Vera, Intent, Vow, Thermite, Prove, NanoLang's mandatory shadow tests), examples/intent as program (Aver, Pact, Prove, reqlan, NanoLang), one canonical form (Tacit, Unison, Codong, Zero, X07, Magpie). The lessons those peers report: proofs must declare their coverage honestly; names-removal does not remove naming bugs; logs saturate; determinism constraints must be enforced by the runtime/VM, not by convention.

### Cited Findings
- Hash chains + replay + VM-enforced effects: Boruna — [entry](https://agentlanguages.dev/languages/boruna/); catalogue essay treats hash chains and determinism as "features, not as evidence of convergence" [opinion] — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)
- Replay by journal in production runtimes and the saturation/double-execution/versioning failure modes — [Particula Tech](https://particula.tech/blog/durable-execution-ai-agents-temporal-inngest-restate)
- Contracts always on with honest proven-vs-runtime split; "A partial proof should be honest about what it covers"; Tier 2 unimplemented; refinement facts lost through ADT fields — [Vera entry](https://agentlanguages.dev/languages/vera/)
- Mandatory tests per function + proved core with explicit out-of-scope list — [NanoLang entry](https://agentlanguages.dev/languages/nanolang/)
- Canonical text + content hash + names as metadata; cost: gives up text tooling, duplicates accumulate — [Tacit entry](https://agentlanguages.dev/languages/tacit/); [Unison](https://www.unison-lang.org/docs/the-big-idea/)
- Structured diagnostics as the agent interface; repair plans; version-pinned skills — [Zero entry](https://agentlanguages.dev/languages/zero/)
- Dhall: semantic-hash-pinned imports and totality, with adoption limited by syntax/errors [author's view] — [Pi Stack](https://www.pistack.xyz/posts/2026-10-09-cue-vs-dhall-vs-pkl-configuration-languages-2026/)
- reqlan: requirement files linked to symbols and tests, broken links fail the checker — [agentlanguages.dev](https://agentlanguages.dev)

### Inferences
- RCE's unique combination is (a) the *proof* that replay reproduces every hash (T3) and (b) the injective canonical form, both mechanised in Lean. Boruna asserts bit-identical replay but offers no proof; Temporal relies on programmer discipline. This is the strongest differentiation claim RCE can make and it is already in the paper.
- The examples-as-gate idea exists elsewhere only as "mandatory test block" (NanoLang) or "intent prose" (Aver/Pact/Prove). RCE's distinct move is that examples are *typed event traces against the Form* (`example Inc, Inc, Dec -> 1`), i.e. executable specs over the same semantics replay uses. No peer found does this.

### Gaps
- No peer publishes post-mortems on hash-chained logs at scale (Boruna has 34 commits). Temporal's saturation data is the only operational evidence and it is secondary.

## KQ6. Failure modes of "best of N languages" designs, and what kept small languages small

### Takeaway
Measured feature agglomeration (Pascal 167 manual pages → Java 891) and the Swift 6 strict-concurrency rollback show that union-of-features designs grow until users route around them; Go's proposal process ("slanted towards declining", 10:1 benefit rule), Zig's "no hidden control flow / no hidden allocations / no macros", and Elm's near-freeze are the documented restraint mechanisms — with Elm showing that stability without a migration path and without governance transparency also loses users.

### Cited Findings
- Singer, Cameron, Alexander (Glasgow, 24 Jul 2014), "Programming Language Feature Agglomeration": keywords Pascal 36, C 37, Java 50, Scala 49; manual pages Pascal 167, C 272, Java 891, Scala 736; Java manual 333→891 pages 1996→2006; "newer languages usually extend older ones rather than replacing their syntax and semantics, so they accumulate features"; remedies: deprecate with warnings, identify an elegant subset, design families of co-evolving languages; limitations: four languages, grammar comparison inconclusive — [ple14.pdf](https://www.dcs.gla.ac.uk/~jsinger/pdfs/ple14.pdf)
- Go 2 process (Griesemer, 29 Nov 2018): a change must address an important issue for many people, have minimal impact on everyone else, and come with a clear well-understood solution; rule of thumb "help at least ten times as many developers as it hurts"; ~120 open proposals, three selected for Go 1.13; two feedback rounds "slanted towards declining proposals" to "keep the language small and clean" — [go2-here-we-come](https://go.googlesource.com/blog/+/master%5E/_content/go2-here-we-come.article)
- Zig: "If Zig code doesn't look like it's jumping away to call a function, then it isn't"; no hidden allocations; no macros; large feature sets "distract from the application itself" — [Why Zig](https://ziglang.org/learn/why_zig_rust_d_cpp/)
- Swift: strict concurrency rolled back toward "approachable concurrency" in 6.2 after adoption pain — [InfoQ](https://www.infoq.com/news/2025/08/swift62-approachable-concurrency)
- Elm: 0.19.1 Oct 2019 → 0.19.2 "Faster builds, and the Road to Elm 1.0" ~Jul 2026, a ~7-year gap; 0.19 removed most native JS interop; forks (Gren, Lamdera); HN split between "Stability. It works." and "seven years of silence", "unaddressed bugs are not stability", closed governance hurting adoption [opinions] — [HN thread](https://hn.svelte.dev/item/48803364)
- Gleam shipped 1.0 (Mar 2024) with a deliberately small feature set (Result errors, immutability, ADTs, no null, no implicit conversions) and has released steadily to 1.14 (Dec 2025) — [Wikipedia: Gleam](https://en.wikipedia.org/wiki/Gleam_(programming_language))
- Carbon: a "best of C++ + safety" successor has slipped 0.1 to "end of 2026 at the soonest" and 1.0 past 2028 — [Carbon roadmap](https://github.com/carbon-language/carbon-lang/blob/trunk/docs/project/roadmap.md)
- Unison and Tacit both report that departing from text costs the editor/tool ecosystem — [Unison](https://www.unison-lang.org/docs/the-big-idea/); [Tacit entry](https://agentlanguages.dev/languages/tacit/)

### Inferences
- The agglomeration risk for RCE is explicit in SURFACE.md's five-source table plus the 0.6–0.8 additions (par, budgets, LVars, sessions, supervisors, actors, indexed text types, Secret, Cap, Guarded). The protective structure RCE already has — a normative EBNF read by the tools, LALR(1) conflict check, two/three agreeing parsers, a Lean core — is the right kind of brake, but the *governance* brake (a Go-style decline-biased proposal rule, a stated keyword/rule-count budget, a per-version "what was removed" line) is not documented in the clone's README/SURFACE.
- Elm's lesson is that "refuse change" is not the same as "small": users left over the absence of a migration path, not the absence of features. For RCE the per-module `# rce-version:` pin plus `rce fmt` canonical rewrite is a migration mechanism; it should be paired with an automatic upgrader (`rce migrate`) before 1.0 so every breaking change ships with its own repair.
- Zig's "no hidden control flow" maps directly onto RCE's "an error is an output in λ and an event in D, never an unlogged throw": the invariant should be stated once in those Zig-style words and used as the test for every future surface proposal.

### Gaps
- No primary source fetched on PL/I, Ada or C++ feature history; the agglomeration paper covers Pascal/C/Java/Scala only. Scala-complexity forum threads surfaced in search but were not read; no quantitative Scala claim made.

## KQ7. Positioning for RCE: adopt, refuse, differentiate

### Takeaway
RCE should position as the only entry in the field that is simultaneously a *proved* replayable state-machine semantics, a canonical injective form, and an admission gate where typed example traces are the program — and it should adopt the cohort's table-stakes agent interface (stable rule codes, JSON diagnostics, repair plans, version-pinned primer) while refusing the syntactic camp's token-minimal surfaces and refusing to let the "five languages" surface grow without a decline-biased process.

### Cited Findings
- Catalogue essay: verification is "the most crowded" camp; syntactic bets are doubted; "sixteen other people have independently reached variations of the same thesis" — [Three camps](https://negroniventurestudios.com/2026/05/20/three-camps-alike-in-dignity/)
- Agent-interface table stakes across Vera, Zero, Tacit, Codong, Vow (stable codes, JSON, repair plans, pinned skills/primers) — [Vera](https://agentlanguages.dev/languages/vera/); [Zero](https://agentlanguages.dev/languages/zero/); [Tacit](https://agentlanguages.dev/languages/tacit/); [Codong](https://agentlanguages.dev/languages/codong/)
- Evidence that in-context primers and test-validated translations close the low-resource gap — [vera-bench](https://github.com/aallan/vera-bench); [MultiPL-T](https://arxiv.org/pdf/2308.09895); [No Silver Bullet](https://arxiv.org/abs/2501.19085)
- Evidence that semantic (checker-driven) decoding beats grammar-only decoding — [Projectional Decoding](https://www.alphaxiv.org/abs/2605.30054.md)
- Evidence that LLMs handle auto-active contracts (Dafny 82%) far better than proof assistants (Lean 27%) — [arXiv 2509.22908](https://arxiv.org/abs/2509.22908v1)
- Evidence that log-as-database designs hit history saturation — [Particula Tech](https://particula.tech/blog/durable-execution-ai-agents-temporal-inngest-restate)
- Evidence that strict checks without ergonomics get rolled back — [InfoQ Swift 6.2](https://www.infoq.com/news/2025/08/swift62-approachable-concurrency)

### Inferences (recommendations; this researcher's synthesis)
- **Adopt**: (1) a stable, versioned rule-code registry with `rce check --json`, `rce explain W-REC-1`, and `rce fix --plan --json` returning edits, not advice (Zero/Vera pattern); (2) a byte-pinned `rce primer --section` for selective in-context disclosure (Tacit/Vera pattern) and ship SKILL.md/AGENTS.md in-repo; (3) an honest coverage report per admission — which obligations were discharged by example replay, which by shadow run, which by Kani, which not at all (Vera's tier split, NanoLang's scope statement); (4) use `rce emit` + `rce test` to manufacture test-validated foreign↔RCE translation pairs as training/few-shot data (MultiPL-T recipe); (5) a log compaction/snapshot design with the same hash-chain guarantee before RCEdb is promoted (Temporal lesson); (6) a Go-style decline-biased surface-proposal rule and a published per-version removed-features line.
- **Refuse**: single-character opcodes, English-keyword operators, SSA-as-surface, De Bruijn-only names (Sever/NERD/Magpie/Vera-slots) — no measured correctness win, demonstrated readability cost, and Vera's own report that naming bugs returned in tooling; JSON-AST-only source (X07) — forfeits text ecosystem per Unison/Tacit; proof-assistant-level obligations on the author (Lean) — 27% LLM discharge rate; Turing-complete config/intent sublanguages (Pkl lesson) — RCE's totality is a feature to protect.
- **Differentiate**: (1) examples are typed event traces over the same semantics that replay and logging use, so the oracle the agent cannot bypass is the program itself (no peer found); (2) replay and canonical-form injectivity are *theorems in Lean*, not runtime promises (Boruna/Temporal have promises only); (3) one Form → five emitted targets with reference traces for cross-checking implementations (`rce trace --json`), which no catalogued language pairs with a proved semantics; (4) explicit energy/cost axis (budgets, size-scaled method costs in 0.7) — absent from every catalogued entry.
- **State the trade**: indentation syntax costs the 25–35% formatting-token savings brace languages can strip; justify it by human review and output-side irrelevance, or offer a canonical compact serialisation (`rce fmt --compact`) for agent contexts — the Form JSON already exists for that role.

### Gaps
- None of the recommendations above are validated by an experiment on RCE itself; the paper's 10,000-Form measurements were not re-examined here for per-rule refusal rates or agent-authorship pass rates.
